# P11.2 病灶放置几何性能与加载状态专项报告

日期：2026-11-17
范围：AI 分割确认后的人体放置入口、首次轮廓准备、拖动结算、确认位置和放置浮层生命周期。
边界：未修改 MobileSAM、上传限制、人体模板、医学图谱、V4 匹配公式或服务器配置。

## 结论

“正在准备人体轮廓”原本执行的是完整的源 MultiPolygon 拓扑校验，并非人体图片加载。真实复杂候选包含 389 个独立片区、690 个环、301 个孔洞和 6018 个顶点；旧实现还在入口和人体校验中重复进行孔洞、片区和边界检查，导致 Apple M4 Node.js 环境首次进入约 23.2 秒。

本轮把同一未修改源几何的完整拓扑校验限制为一次，并缓存源指纹。之后由已验证源经过正数等比缩放和旋转得到的几何走可信快速路径：仍检查每条边和完整填充面是否位于人体内，但不再重复片区内部和孔洞间拓扑检查。真实样本首次入口在相同环境降为约 263 ms，快速人体边界校验约 9.1 ms。

拖动期间，变换参数只保留在 Canvas 组件内，用已缓存位图和单帧合并绘制；页面、V2 会话和正式人体几何不会随每个 `touchmove` 更新。松手才执行一次正式变换和一次人体边界校验。普通拖动后不再显示加载遮罩；首次人体 viewport 尚未就绪时也只在工作区内显示不拦截触摸的轻量提示。缺数据、Canvas 失败和超时现在分别报告 `waiting`、`error` 和可恢复操作，页面不会永久等待。

## 根因

旧调用链重复执行了同一类工作：

1. `preparePhotoGeometry()` 逐环检查闭合、重复点、自交、面积和全部孔洞/片区关系。
2. 初始人体几何再次调用 `validatePlacementGeometry()`，重新从零构建环和边索引，并再次执行内部拓扑和人体边界检查。
3. 松手和确认还会重复完整拓扑检查。
4. 草稿的复杂结构和 DPR 序列化使问题进一步放大。

热点并非坐标变换。真实样本的单个相似变换只有约 0.4 ms；旧实现约 11.8 秒用于照片源拓扑准备，约 11.6 秒用于重复的人体几何完整校验。

## 实施

- [placement-geometry.ts](../../../miniprogram/utils/placement-geometry.ts:97) 为每个环一次性构建点、边、包围盒和 Y 轴索引；孔洞包含、环相交和片区重叠复用这些派生数据。
- [placement-geometry.ts](../../../miniprogram/utils/placement-geometry.ts:304) 以 session、photo、result、candidate、prompt revision、Mask 摘要、尺寸和实际几何生成源指纹；只缓存完全一致且已冻结的源结果。
- [placement-geometry.ts](../../../miniprogram/utils/placement-geometry.ts:427) 增加可信变换快速校验。它仍执行全部人体表面和人体孔洞检查；不可信、被篡改或后端裁剪后的几何继续使用完整校验。
- [placement-session.ts](../../../miniprogram/packages/clinical/state/placement-session.ts:79) 入口、拖动结算、滑块结算和视图切换使用可信快速路径；重新编辑未知历史几何仍执行完整检查。
- [annotation-session.ts](../../../miniprogram/state/annotation-session.ts:145) 确认时只有源指纹仍匹配的来源对象才复用；否则重新完整准备和校验。裁剪结果始终重新完整校验。
- [placement-overlay.ts](../../../miniprogram/packages/clinical/components/placement-overlay/placement-overlay.ts:51) 把高频移动留在组件内，合并到 Canvas 单帧；源贴图只缓存一次。
- [placement-overlay.ts](../../../miniprogram/packages/clinical/components/placement-overlay/placement-overlay.ts:59) 明确发送 `ready / waiting / error`；异步绘制完成后重新核对 key、revision 和 viewport，过期结果不能确认新状态。
- [placement.ts](../../../miniprogram/packages/clinical/pages/placement/placement.ts:78) 区分首次加载、普通重绘、等待和失败。首次 8 秒无就绪会重试一次，再超时才显示可恢复错误。
- [placement.wxml](../../../miniprogram/packages/clinical/pages/placement/placement.wxml:1) 全屏加载只由 `initialReady` 控制；首次成功后的 revision 更新显示轻量“正在校正病灶范围”，人体画面保持可见。

### 就绪握手补充修复

真机复测出现“人体轮廓或病灶范围加载超时”但页面没有绘制错误。定位为页面在 `nextTick` 后再次比较视口字符串，人体首帧和布局同步之间到达的有效已绘制回执会被丢弃。现在：

- 放置浮层回执同时携带 `layoutRevision` 和本次实际绘制的 viewport，不再只传派生字符串。
- 页面直接接受与当前 interaction key、revision 和 layout revision 匹配的实际绘制视口；旧布局回执仍被拒绝。
- `waiting` 和 `error` 不再因为页面暂时没有 viewport 而被静默忽略。
- 每次人体 viewport 完成页面同步后主动唤醒浮层重绘，避免组件已经创建但首帧查询停在旧状态。
- 兼容旧回执仍要求 viewport 字符串与页面当前值一致，因此聚焦视图的旧帧不能确认全身视图。

## 拖动与确认

- 120 次移动：正式几何变换 0 次，完整拓扑校验 0 次，页面组件桥事件只保留开始和结束。
- 松手：正式变换 1 次、可信人体边界校验 1 次、完整内部拓扑校验 0 次。
- 确认：再次变换并复核可信人体边界 1 次、完整内部拓扑校验 0 次。确认仍比较页面预览和重新计算结果，不能提交形状不一致的数据。
- 每次移动更新缓存位图的相似变换和必要十字/包围框，不遍历原始 MultiPolygon。
- 最终坐标取最后一次有效触点，快速松手不丢点。

## 加载与错误恢复

- 首次进入：只在人体工作区显示 `正在准备人体画布…` 或 `正在准备病灶范围…`，不覆盖整个人体页面，也不拦截触摸。
- 人体 PNG 未就绪时先使用同一冻结模板的轮廓绘制占位并发布 viewport；PNG 到达后原位替换，不等待网络图片才解除页面等待。
- 首次后的拖动、缩放、旋转和视图重绘：不清空人体画面，不恢复页面遮罩，也不重新创建完整人体背景。
- 输入暂缺：Canvas 组件发布 `waiting`，页面保留可恢复状态。
- 初始化或绘制失败：发布 `error`；首次失败显示整体重试，后续失败只提供“重试显示”。
- 首次 watchdog：1.2 秒未就绪时自动重试一次；第二次仍失败才显示明确超时，不伪造 ready。
- 页面销毁、隐藏、来源切换和 revision 变化：旧帧、旧触摸查询和旧错误不能覆盖新状态。

## 几何正确性

- 完整校验仍拒绝自交、非法孔洞、孔洞越界、片区重叠、片区共用边、人体外和跨越人体空白区域。
- 真实 389 片区、301 孔洞样本经快速路径后仍为 389 个片区，孔洞没有被合并或填充，快速与完整校验结果完全一致。
- 可信路径只接受由已通过完整校验的冻结源，经正数等比缩放和旋转产生的几何。
- 人体交集返回的新 MultiPolygon 不接受可信捷径；保存前执行完整拓扑和人体校验。
- 缓存指纹包含 Mask 摘要和几何内容；换图、修改候选或修改顶点会使旧缓存失效。

## 后续判断

当前真实复杂样本已从约 23 秒降到 0.26 秒 Node 计时，未发现必须立即引入 Worker 或轮廓简化的证据。若真机仍有明显同步长任务，或出现超过 20,000 顶点/1024 片区的结果，应优先使用微信 Worker 做源轮廓准备；轮廓简化必须保留多片和孔洞，并单独评估面积偏差，不得静默删除小病灶。
