# 修改前后对照

## 基准方法

- 旧实现：Git 提交 `27b41f6744c264fbabb3af1bf08ac0b99075cfda` 中的 `placement-geometry.ts`。
- 新实现：本轮未提交工作区中的生产 TypeScript。
- 环境：Apple M4，macOS arm64，Node.js v24.11.1。
- 数据：普通 50/2000 顶点、真实 MobileSAM 389 片区样本的 candidate-2，以及 500/1000/2000 孔洞合成几何。
- 每个样本都使用同一个有效背面人体位置，确保完整检查所有边和填充面，不用“第一处越界就提前退出”的结果掩盖热点。

## 总耗时

| 样本 | 修改前 | 修改后 | 加速比 |
|---|---:|---:|---:|
| 50 顶点 | 3.696 ms | 1.228 ms | 3.0x |
| 2000 顶点 | 9.501 ms | 6.035 ms | 1.6x |
| 6018 点、389 片区、301 孔 | 23,213.949 ms | 263.497 ms | 88.1x |
| 500 孔洞 | 5,220.572 ms | 12.714 ms | 410.6x |
| 1000 孔洞 | 20,664.641 ms | 28.448 ms | 726.4x |
| 2000 孔洞 | 82,606.447 ms | 66.690 ms | 1238.7x |

“总耗时”由照片源拓扑准备、照片到人体变换和最终人体校验组成；不包含页面导航、微信组件桥、原生 Canvas 栅格或网络。

## 调用次数

- 旧入口：同一源几何在源准备和人体校验中执行两次完整内部拓扑工作。
- 新入口：同一源只准备一次；入口人体校验走可信快速路径。
- 旧拖动结算：每次松手完整拓扑校验。
- 新拖动结算：每次松手一次变换 + 一次快速人体边界校验；完整拓扑校验 0 次。
- 旧确认：再次完整准备/校验。
- 新确认：只有源指纹仍匹配时复用可信来源，再次执行一次变换和一次快速人体边界校验；无法证明可信时回退完整校验。

## 解释边界

这组数字是 JS 几何工作耗时。微信真机可能受 JS 引擎、CPU 降频、组件桥、Canvas 和内存 GC 影响，不能把表中的加速比直接写成手机帧率或首帧时长。
