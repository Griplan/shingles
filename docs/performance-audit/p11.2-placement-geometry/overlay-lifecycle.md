# Canvas 浮层生命周期

## 状态

`placement-overlay` 向页面发送三种明确状态：

- `ready`：当前 key、revision 和 viewport 对应的稳定帧已经绘制。
- `waiting`：必要输入暂缺，或 Canvas 尚未可用；不是成功。
- `error`：节点、上下文或绘制失败；不是成功。

绘制开始保存 key、revision 和 viewport 快照。异步初始化后如果输入已变化，旧任务不会再发布 ready，而会重新排队当前状态。

## 页面显示

- 页面不再使用全屏加载遮罩。
- 人体首帧未完成时，只在固定人体工作区内显示 `正在准备人体画布…`；该提示不拦截触摸。
- 人体本地 PNG 未就绪时，先以同一冻结模板的轮廓绘制占位并发布 viewport；PNG 到达后再替换，不把图片加载当作整页阻塞条件。
- 首次 ready 后，拖动结算、缩放、旋转和 revision 更新只保持原画面。
- 普通重绘需要等待时在控制区显示“正在准备病灶范围…”，不隐藏人体。
- 首次错误显示“人体轮廓或病灶范围加载失败，请重试”。
- 首次超时显示“人体轮廓或病灶范围加载超时，请重试”。
- 已初始化后的错误只显示“重试显示”，不遮挡整个人体。

## 超时和重试

- 首次 watchdog 为 1.2 秒。
- 第一次超时只发起一次组件重试并继续保持等待。
- 第二次超时变为可恢复错误，不会伪造 ready。
- 页面销毁时清除 watchdog。
- 页面隐藏、来源切换和 interaction key 改变会取消旧绘制帧。
- Canvas 节点/上下文失败可由 `retry()` 重新测量和初始化。

## 测试

- 缺 viewport 发布 waiting。
- Canvas 初始化失败发布 error。
- 恢复后发布 ready。
- 首次 ready 后的 revision 变化不重新显示阻塞遮罩，也不清空已显示的人体。
- 120 个高频变换合并为一个待绘制帧。
- 页面隐藏取消待绘制帧，恢复后复用贴图。
- 来源切换后，旧异步帧不能确认新来源。
