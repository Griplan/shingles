# 02 前端照片准备与结果展示

## 照片准备

P8.1 已把原图接收上限与最终上传上限分开：

| 阶段 | 上限 |
| --- | --- |
| 原图 | 50 MiB、5000 万像素 |
| Canvas 安全预算 | 20 MiB、1600 万像素、单边 8192 px |
| 上传与交互基准 | 8 MiB、300 万像素、最长边 1920 px |

超过 Canvas 安全预算的图片优先调用微信原生 `wx.compressImage`；不会先把原分辨率图创建为 Canvas RGBA。单图串行、原生缩图 30 秒超时、迟到结果清理和失败降级保留。相关实现见 `miniprogram/packages/clinical/utils/prepare-photo.ts`。

P10 本机用 4032×3024 样图走生产页面代码，处理到 1920×1440 的耗时约 221–236 ms。该数值来自 Node/Pillow 适配器，不是手机原生缩图时间。P8.1 历史本机证据中，6000×4000 和 8064×6048 分别约 276 ms 和 250 ms；4800 万像素 EXIF 旋转例约 386 ms。它们同样不能替代 Android/iOS。

## 上传

本机暖启动上传约 145–157 ms；云端公开测试图上传统计约 159 ms。上传前最终文件复核了大小、宽高、格式和方向。测试中框选坐标最大误差约 `1.6e-13` 个处理图像素，确认多边形与 Mask 像素中心重建差异为 0。

## 结果解析与候选切换

分割返回候选元数据后，前端只为当前候选下载 alpha Mask；切换候选不会再次调用 MobileSAM。本机三次候选切换为 20.6–21.4 ms，云端 20.7 ms。候选切换需要重新读取、缓存和绘制对应 Mask，但不是主要系统热点。

## Canvas 与页面跳转

照片 Canvas 当前每次重绘都会：

- 查询 `#photo` 节点和尺寸；
- 获取 context；
- 清空并重画照片与 Mask；
- 画提示框/点或笔刷预览；
- 调用 `setData({error:""})`；
- 触发 `renderstate`。

client 坐标触摸还会单独查询 `boundingClientRect`。120 次框选移动的结构计数见 [05-touch-and-canvas.md](05-touch-and-canvas.md)。这是已确认的结构性问题，但手机屏幕延迟仍为 `NOT_MEASURED`。

放置页的 Canvas 已经复用节点，并用 `requestAnimationFrame` 合并绘制；拖动中只传平移量，调整期间后端请求为 0。照片确认到导航调用约 0.12 秒，导航到放置可交互约 0.02 秒。

## 内存与生命周期

- 照片处理采用单图串行，避免同时解码多张大图。
- 候选图片按路径缓存；换图/换候选时清理不再使用的图片对象。
- 页面卸载和取消会撤销临时照片和待处理状态。
- 本机脚本未测微信原生图片解码、JS heap、GPU 和整机 RSS。

## 当前边界

当前体验版实际版本无法确认。历史 `0.6.8` 上传成功不等于手机已设为体验版；P8.1、P9 和本轮审计代码都没有自动进入客户手机。因此本机前端结果只能说明当前源码路径。
