# 01 全链路调用与耗时

## 业务路径

```text
选择照片
→ 读取格式/大小/宽高
→ EXIF 与缩放压缩
→ 上传处理图
→ 创建临时 AI 会话并保存方向修正后的 PNG
→ 框选
→ 本地裁剪推理
→ MobileSAM 图像编码
→ box/point 提示与 Mask 解码
→ Mask 后处理及 MultiPolygon
→ 返回候选元数据
→ 下载实际候选 alpha Mask
→ Canvas 绘制
→ 用户确认照片坐标结果
→ 进入人体放置
→ 本地拖动/缩放/旋转
→ 最终几何校验并保存 V2
→ 调用 V4 匹配并展示
```

照片坐标、人体坐标和展示坐标没有混用。处理后的 1920×1440 图是框、点、Mask、多边形和确认结果的共同照片坐标基准；人体放置仍从照片 MultiPolygon 和最终相似变换重算。

## 测量口径

- 前端阶段使用同一进程单调时钟；后端 AI 阶段使用 Python `perf_counter`。
- 网络阶段只统计客户端请求前后的单调时间，不跨机器相减时间戳。
- 本机暖启动是模型已加载、同一服务连续运行的三次完整链路；冷启动另起模型进程。
- 用户选择照片、人工框选和人工拖动时间不进入系统等待。
- Canvas 命令提交时间不等于原生 raster、触摸桥接或屏幕刷新时间。

## 本机完整链路

输入为 4032×3024、约 1.27 MB 的公开 CDC 样图，处理为 1920×1440、约 0.33 MB。

| 阶段 | 冷启动 | 暖 run 1 | 暖 run 2 | 暖 run 3 | 暖 P50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 照片准备 | 235.5 | 222.9 | 221.5 | 229.6 | 222.9 |
| 选图到照片可框选 | 581.4 | 572.9 | 544.1 | 575.7 | 572.9 |
| 上传 HTTP | 157.1 | 147.3 | 145.2 | 149.1 | 147.3 |
| 第一次 MobileSAM | 2,355.0 | 752.7 | 736.1 | 760.0 | 752.7 |
| 框选松手到 Mask 可交互 | 2,376.0 | 757.3 | 753.7 | 776.7 | 757.3 |
| 候选切换 | 21.4 | 21.2 | 21.4 | 20.6 | 21.2 |
| 照片确认 | 21.3 | 21.0 | 21.0 | 21.6 | 21.0 |
| 确认到导航调用 | 129.0 | 115.2 | 117.8 | 127.4 | 117.8 |
| 导航到放置可交互 | 22.0 | 21.8 | 21.2 | 21.1 | 21.2 |
| 放置确认到匹配完成 | 278.8 | 324.7 | 275.1 | 348.7 | 324.7 |

暖启动各阶段合计约 1.83 秒；冷启动约 3.43 秒。这里包含确认、导航、放置和匹配，不等于模型单次耗时。

## 腾讯云完整链路

使用 700×460 公开测试图，避免把大图直接交给云端 CPU；HTTP 公网测试入口只用于开发联调。

| 阶段 | 实测 |
| --- | ---: |
| 选图到照片可框选 | 682.6 |
| 上传 HTTP | 158.7 |
| 第一次 MobileSAM | 3,795.0 |
| 第二次 MobileSAM | 3,672.4 |
| 框选松手到 Mask 可交互 | 3,820.7 |
| 候选切换 | 20.7 |
| 照片确认 | 42.2 |
| 确认到导航调用 | 60.5 |
| 导航到放置可交互 | 21.3 |
| 放置确认到匹配完成 | 435.7 |

系统等待合计约 5.08 秒。上传不是主要问题；云端模型推理与返回是主要系统等待。

## 结论

1. 本机暖启动可以开始框选的中位时间约 0.57 秒，云端约 0.68 秒。
2. 本机暖启动首个 Mask 约 0.76 秒；冷启动约 2.38 秒。
3. 云端低负载首个 Mask 约 3.82 秒。
4. 候选切换、导航和放置初始化都在约 0.02 秒量级。
5. 客户手机实际时间、触摸掉帧和 FPS 尚未测量。
