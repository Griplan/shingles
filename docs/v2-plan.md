# V2 开发计划：病灶多边形标注、多区域管理与会话暂存

本文件保留**2026-10-22原计划**（第1～11节，时态和NOT_RUN为当时记录），文末第12节记录2026-10-23实际采用方案与差异。用户已授权实施完整V2.1～V2.5；不能将历史计划状态当作当前状态。唯一进度、失败和验收结果见[task.md](../task.md)，不在此维护第二份进度台账。

## 1. 目标、边界和开工条件

V2回答“用户在当前标准人体上标出了哪些具体范围”。实现逐点圈选、顶点/线/填充、撤销/取消/有效闭合、多片管理、删除、独立正背面、同一运行会话暂存和范围复核。入口粗部位只决定初始视图和聚焦；从胸部进入也允许返回全身，画跨胸腹的有效人体范围，不按胸部分区裁切病灶。标注时隐藏V1整块粗部位高亮，保留人体与必要导航文字。

不做自由画笔、橡皮擦、顶点拖拽、复杂双指手势、自动合并/凸包、照片/自动配准、AI、医学诊断/置信度、皮节匹配、后端评估调用、数据库、账号病例、云保存、跨启动可靠恢复或3D。正式医学图谱仍空、未验证、禁用；V2不需要先取得它，V3的图谱准入不能被绕过。

**当前没有经证实、必须先重做V1才能启动V2.1的阻塞。** 实际精确触点/多机型仍有NOT_RUN风险，不能当作坐标已错或全部已验。下面P项是V2新增能力的阶段门槛，不是声称V1已有这些能力：

| 编号 | 实际缺失/风险 | 处理阶段与阻塞范围 |
| --- | --- | --- |
| P1 | 当前Canvas只有regionprobe/debugprobe，focused普通点击忽略；没有标注点事件 | V2.1扩展显式模式与有效annotationpoint，验证聚焦也能输入；未通过不能进入V2.2加点 |
| P2 | renderer无病灶层；lesion-editor目录只有.gitkeep | V2.1证明新增图层共用实际ViewportTransform；V2.2实现顶点/线/填充。不能把两个独立测量Canvas叠起来后假定配准正确 |

## 4. 数据方案（仅文档，不是已存在的TypeScript/API）

以下是V2本地设计，字段名称需在V2.1授权实施时冻结；`schemaVersion:1`也是拟新增本地数据结构版本，不代表已发布。与现有NormalizedPoint对象形式一致；后端草案点对形式留到V4适配。

```ts
// 拟新增 miniprogram/types/annotation.ts；本轮没有修改该文件或业务类型。
type EditorPhasePlan = "editing" | "review";
interface BasisPlan {
  templateId: string;       // commons-neutral-v1
  templateVersion: string;  // 4.0.0
  geometryId: string;       // commons-blank-cc0-v1
  regionSetId: string;      // commons-blank-cc0-v1-ui-regions-2
}
interface NavigationContextPlan {
  entryRegionId: string | null; // 仅“从哪里进入”，不表示实际覆盖范围或医学标签
}
interface DraftPlan {
  id: string;
  view: BodyView;
  vertices: readonly NormalizedPoint[]; // 开放点列，不重复首点
  navigation: NavigationContextPlan;
}
interface CompletedPolygonPlan {
  id: string;
  view: BodyView;
  ring: readonly NormalizedPoint[]; // 验证通过的简单闭合外环；末点显式重复首点
  navigation: NavigationContextPlan;
}
interface ViewSessionPlan {
  completed: readonly CompletedPolygonPlan[];
  draft: DraftPlan | null;       // 每视图最多一份草稿
  selectedId: string | null;     // 只可指向本视图完成列表
  focusRegionId: string | null;  // null为全身；只影响视口，非标注范围
}
interface AnnotationSessionPlan {
  schemaVersion: 1;
  sessionId: string;             // 本地运行内唯一，不是患者/病例ID
  basis: BasisPlan;
  currentView: BodyView;
  phase: EditorPhasePlan;
  revision: number;              // 每次原子数据修改递增，拒绝异步旧事件
  views: { front: ViewSessionPlan; back: ViewSessionPlan };
}
```

只有`state/annotation-session.ts`持有一个活动会话的权威可写状态。页面setData和Canvas props只是只读派生快照；所有加点、撤销、闭合、选中、删除、切面、复核通过同一模块操作并原子更新revision。页面不维护第二套可独立变更的标注数组，也不在组件WeakMap藏另一份病灶草稿。返回/重入读取同一sessionId和最新快照；迟到触点需同时匹配sessionId、revision、模板/view、模式与组件generation，不得在撤销/切面后补入旧点。

草稿不等于已完成区域；每次成功修改就同步写运行内存，不等离开页才保存。唯一ID在本地生成且不复用，不引入UUID库或浏览器专属API；冲突与重入在V2.1测试。selectedId无效/被删除后清空，不误删其他片。UI的idle/drawing/selected状态由draft与selectedId推导，不重复存一个可能冲突的status字段。draft存在时selectedId必须为空。

**闭合约定**：草稿开放；用户显式点“闭合区域”时构造候选闭环，末点复制首点，至少4个数组项、3个不同非共线顶点。只在完整校验通过后加入completed并清草稿；不以“点击靠近首点”吸附闭合。完成环显式首尾重复，与[atlas-spec.md第3节](atlas-spec.md)的未来闭环草案一致；当前V1 UI outline隐式闭合仍保持原约定，它不是病灶数据。绘制完成环时可去掉末项再closePath，不能重复转换或改变存储点。无孔、无多环；不连续片分别存为完成对象。

不保存screen/canvas/backing-store像素、DPR或ViewportTransform到ring/vertices。调试DebugPoint留在现有独立开发路径，不进入会话。session绑定basis，解读任一点还必须带view，独立对象导出时不能丢掉会话basis。V2没有atlas_version、节段、置信度、评估状态字段。

## 5. 入口、模式、状态与导航决策

### 5.1 从V1进入

未来只在当前选择有效时启用“开始标注”。入口先校验模型/区域绑定，创建或复用活动会话，再导航到现有`/pages/annotate/annotate`。路由只传`sessionId`、`view`、`entryRegionId`等小型标识，不携带整组多边形/草稿或JSON焦点矩形。页面从会话basis和同版模型取模板、当前view与入口region.bounds，得到初始聚焦信息；URL不是数据权威。错版、错面区域、过期会话或当前有未处理草稿，必须走校验/导航保护，不能悄悄新建会话并假装恢复成功。

首次新会话在V2.2接通绘制后可由“开始标注”意图建立一个**空草稿**进入drawing，用户直接轻触加首点；空草稿不是假病灶，不计入完成数量。V2.1只演示上下文/状态，不生成模拟点。已有会话重入优先恢复原草稿；有完成区域且无草稿时回idle或review，不自动清列表或重开新片。重复点击入口不得重复创建会话。

### 5.2 单次触摸的唯一用途

未来body-canvas增加一个明确的输入模式（命名建议`interactionMode`），由页面根据状态派生，不让多个可写布尔开关相互争抢：

| 优先级/场景 | 点击用途 | 禁止的副作用 |
| --- | --- | --- |
| 弹层、确认对话或未测量/未加载 | 不向底图发输入 | 不透传选区/顶点/调试 |
| 调试开启 | 仅debugprobe及单个十字 | 不加病灶、不换粗区域 |
| annotate且当前有草稿 | 仅有效annotationpoint（拟新增事件） | 不触发regionprobe或自动放大 |
| annotate的idle/selected，或review | 只读；用完成列表选择/“新增区域”开始绘制 | 不误把随手触摸变成新草稿；不改已有形状 |
| V1浏览overview | 保持原粗区域选择 | 不采集病灶 |
| V1浏览focused | 保持原普通点击忽略 | 不采集病灶 |

标注输入在全身或聚焦视口均可工作，不能照搬当前zoomRegion存在就忽略普通输入的条件。触点经过同一个readTouch/新rect/probeTouch；保持8 CSS px滑动阈值、多指/取消/一次touch只发一次以及异步失效。发生缩放/重测的中间点击应拒绝重试，不使用旧视口。人体图、顶点、草稿线、闭合填充和调试十字由同一个Canvas的同一个已发布视口变换绘制；UI显示时可在像素域画固定大小顶点，但持久值仍是标准坐标。

### 5.3 编辑动作

| 派生状态/动作 | 确定的行为 |
| --- | --- |
| idle：无草稿、无选中完成片 | 显示完成列表与“新增区域”；不自动添加顶点 |
| “新增区域” | 创建当前view的一份空草稿，清selectedId；已有非空草稿时先处理，不覆盖 |
| drawing：草稿可为0、1、2或更多点 | 合法轻触加点；显示开放线及顶点；完成区仍可见，不能误认为草稿已保存 |
| “撤销” | 只去当前草稿末点；为空时禁用，无草稿不影响完成列表 |
| “取消当前区域” | 草稿非空则确认后仅清本草稿；空草稿直接清，完成列表不变 |
| “闭合区域” | 完整校验通过才加入completed；错误保留原顶点，说明问题位置，不静默修形 |
| 从完成列表选某片 | 无非空草稿时进入selected并突出此ID；有草稿先完成/放弃/取消操作。首版不做Canvas选片热区竞争 |
| selected：“删除区域” | 明确显示所选片/view并确认，只删这个ID；selectedId清空，其他片不变 |
| “清空全部” | 不列首版V2范围，避免跨面误删；若另行加入必须明确仅当前view且确认，禁止无提示清空两面 |

多个完成区域允许几何重叠，但保留独立ID、各自ring和明确提示；不合并、不连线、不取凸包、不自动删除被覆盖片。删除一片不改变另一片覆盖。V2不做面积统计；V3若要统计，必须另定同视图并集去重策略，不能相加重复面积。

### 5.4 切面、返回与复核

切front/back前若有非空草稿，提供“完成并切换 / 放弃草稿并切换 / 取消切换”；完成须先通过完整校验，失败留原view/草稿。空草稿无数据可直接切换并清掉；已完成片始终留在各自views中。新面默认全身或该面已记录的focus，不复用另一面的点、选中ID或调试十字。切面不静默丢草稿。

受控返回选择页：非空草稿提供“保留草稿返回 / 放弃草稿返回 / 继续编辑”，已完成片都保留；重入从同一会话恢复。控件触发的导航先完成会话操作后跳转，连点与过期确认需按revision拒绝。系统导航栏返回/手势返回与受控按钮不同：逐操作同步已保住运行内存，onHide/onUnload只清测量/回调/页面订阅，不删除会话；V2.1另在目标基础库核验是否有可用的离开提示能力，未核验不得承诺所有系统返回都可拦截。

进程被系统终止、关闭后重新启动或开发工具重编译可能丢失全部内存；不能保证拦截、保存或恢复。过期sessionId显示“本次运行会话已结束，请重新开始”，不显示假的恢复成功。明确页面文案“仅在本次运行会话内暂存，关闭或重启可能丢失”。不写storage、数据库、文件、云端或患者资料。

“完成标注”先检查两面草稿；若非当前面也有非空草稿，先提示切去处理，不能忽略。处理非空草稿（完成/放弃/取消）后，至少有一片有效完成区域才进入**annotate同页review状态**，默认只读展示两面独立范围列表、数量、当前view及模板和会话限制；可“继续修改”回editing，用同一模块，不新建第二套数据。不跳到现有result占位页，不显示节段、医学概率或虚构的后端评估进度。零片时提示尚无有效区域，不伪造结果。

## 6. 几何有效性与整个区域的人体包含

V2.2拟新增纯函数校验，输入标准点和对应view的bodyOutline，返回成功或可定位的错误（非法点、点数、重复/退化、自交、背景跨越等）；失败不修改输入。无医学类别推断。

闭合保存前至少检查：数值类型且有限（布尔/字符串不是坐标）、[0,1]范围；至少3个不同、不共线顶点；不接受连续重复或非闭合用途的重复顶点；显式闭合、非零面积；没有自交、非相邻边接触/回折重叠；没有孔、多环或跨视图点。保持用户点序，顺/逆时针都合法，不为了“修复”改点序或取凸包。重复误触反馈后拒收新点，不偷偷合并或移动已有点。

**所有顶点在人体内只是必要条件。** 必须证明完整环的每条边（包括最后闭合边）和填充区域都包含于有效人体。手臂到躯干、两腿间、手指凹口的连线可能越过背景；稀疏抽样或只测顶点均不算通过。首选向用户说明“范围跨过人体外，请调整点位或拆成多片”；不裁切为新多边形、不吸附、不静默修复。

现有源外轮廓是V2完整校验的候选几何输入，不是现成能力：V2.2先复核单环有效性/无孔假设、细缝与源像素误差，再实现可验证的完整区域包含判定。可以论证单纯外环条件下完整边关系与内部关系，或验证集合差的等价判定，但必须覆盖切点、共边、凹口与闭合边，不能未经证明只做分段少量采样。用已有后端Shapely在**离线测试**作独立几何对照，不在V2运行时调用后端、不把Python库当小程序依赖。若需要第三方前端库，先评估兼容性/许可/体积并另行确认；本轮不选库或编写算法。未能可靠证明整片包含时，P4保持未完成，禁止保存，不先做假闭合。

容差分别记录，不能混用：

| 类型 | 基线/拟实施规则 | 用途与门槛 |
| --- | --- | --- |
| 手势移动 | 已有8 CSS px | 区分滑动与轻触，不是几何扩大热区 |
| 单点人体探测 | 已有0.25逻辑单位 | 仅单点边缘判断，不移动坐标；不自动授权整片越界 |
| 坐标舍入 | coordinate.ts已有1e-12归一化机器误差修正 | 不改变公式，不拿它当触摸热区 |
| 新几何计算比较 | 拟采用1e-12归一化长度比较、1e-10归一化面积退化阈值 | 是待验证初值，V2.2以独立几何夹具/边界上下两侧样例冻结并记结果，不是已测精度或临床阈值 |
| 整片人体边界 | 首版不扩大人体或缓冲成热区；只容许经验证的数值比较误差 | 探测因0.25逻辑单位接受的边缘点若使整片不包含，闭合时仍明确拒绝；源栅格简化误差不靠随意放宽阈值掩盖 |

初步输入规模建议每环最多128个非闭合重复前的顶点、每view最多20片；这是待V2.2/2.3性能与可用性验证的上限方案，不是现有能力或已测容量。超限说明原因并保留已有数据，不截断或自动降采样。性能未证明前不得扩大到任意规模。

## 9. 最终实际验收场景（未来执行）

选择正面胸部 → 开始标注并进入正确聚焦 → 点击若干点、验证并闭合第一片 → 新增第二片并闭合 → 选中并删除第二片 → 返回全身查看 → 返回选择页 → 再进入同会话 → 第一片仍在同一位置 → 切换背面并新增独立片 → 切回正面，原标注仍正确。

同时执行：不足3个有效点不可完成；自交/跨人体外片不能入列表；取消草稿不清完成片；缩放复位不改标准坐标；从胸部进入不强制限制范围于粗胸区；review没有神经节段/概率/假API；运行内暂存和重启失效说明真实。保留创建/草稿/错误/双片/删除后/重入/两面/复核截图和环境。不得拿静态SVG、HTML或Node替身代替微信真实渲染；无法运行则NOT_RUN并列操作步骤。

## 12. 实际采用方案及差异（2026-10-23）

第1～11节是原计划快照，实际进度仅见task。已采用原定annotation类型、唯一session单例、纯几何、同一body-canvas/viewport的lesion-render、同页review；未另建编辑器组件或结果页。人体4.0.0、geometry/regionSet及归一化公式保持原值。草稿开放、完成环显式重复首点，维持第4节约定。

差异及原因：

- 测试按实际职责集中为annotation-geometry.test、annotation-session.test、annotation-flow.test，并扩展既有canvas.test，避免把同一套替身复制成多个文件；新synthetic夹具仅位于backend/tests/fixtures。
- 人体包含采用完整边界交点切分及孔洞内部检查，无新增运行时依赖。所有交点决定恒定归属的区间，再检查每一区间，不是稀疏抽样。当前两面源轮廓为一个无孔简单环（独立审核）；BodyGeometry可表达多个非相交部分与孔洞，但未来模板适配必须提供实际结构。
- 同时最多一个活动草稿，由切面原子处理保证；每面draft字段遵循原结构，不能把另一面未处理草稿藏起来。
- “完成标注”非空草稿提供继续/放弃后完成/取消，按本轮最新指令落实；切面仍支持验证闭合后切换。完成复核默认两面全身，只读查看/切面，再继续修改。
- 单例open重入优先恢复已有草稿及其原视图；无草稿时复用同会话并采用有效入口聚焦。route只含sessionId；当前view/basis/navigation从权威会话读取，不从URL覆盖数据。
- 点/片数上限采用128/20，资源上限拒绝不截断。数值误差长度1e-12、退化面积1e-10归一化单位；严格包含不继承0.25逻辑单位触摸容差。真机容量/低端性能待验证。
