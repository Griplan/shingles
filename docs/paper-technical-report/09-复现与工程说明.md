## 2. 环境

开发实验：macOS Apple M4／16GB，Python 3.12 系列；本次Python实际环境与安装包快照见 [environment.json](audit/environment.json)。Node 24.11.1；TypeScript 5.9.3；miniprogram-api-typings 5.2.3。Python最低要求3.11，Linux实测3.12.3。AI关键依赖固定Torch2.5.1、torchvision0.20.1、timm1.0.12、NumPy2.1.3、Pillow11.1.0、Shapely2.1.2、pytest8.3.5、psutil6.1.1。

Linux CPU 使用 `deployment/requirements-linux-cpu.lock`，不能在CPU服务器按开发机MPS环境推断运行行为。后端pyproject部分为版本范围；复现已发表性能时应采用实际环境锁定结果，不直接安装“最新”。微信开发者工具版本和设备需由复现实验单独记录；测试库版本不等于手机微信版本。

已有环境可直接复核。新环境建立独立venv，按仓库 `ai/README.md` 和Linux锁文件安装；模型仅从官方固定版本取得，校验后使用，不应重复下载已有权重。权重、原始实验输入和临时结果均不提交Git。若无合法图像先用项目合成样本，不上传患者图片。

## 4. 后端本地启动说明（本次未新启动）

在已具备AI依赖的解释器环境、仓库根目录运行，示例仅绑定loopback且端口应先确认空闲：

```bash
DERMATOME_ENV=development ENABLE_REFERENCE_MATCHING=1 ENABLE_AI_SEGMENTATION=1 AI_DEVICE=cpu \
  ai/.venv/bin/python -m uvicorn app.main:app --app-dir backend \
  --host 127.0.0.1 --port 8001 --workers 1 --no-access-log
```

`AI_CHECKPOINT`可指定合法固定权重；默认从仓库定位。`AI_TEMP_ROOT`应为私有可写目录，不可放公共static目录；服务内部使用独立子目录。不要把示例改为公网0.0.0.0然后省略身份保护。正式云端配置与本地development不是同一安全模式，见[05](05-系统总体架构.md)。

健康请求示例：`GET http://127.0.0.1:8001/api/v1/health`。匹配服务显式开关启用后才接受参考几何。AI依赖缺失时手工几何仍可用。端口被占用不要停止未知进程。

## 5. 可复核的接口样例

完整匹配输入以 `backend/app/schemas/evaluate.py` 为准。下面为**结构示例**，实际多边形须在当前体表内；哈希必须取当前数据，不能用过期值重试绕过409：

```json
{
  "request_id": "research-case-001",
  "annotation_revision": 1,
  "identity": {
    "template_id": "commons-neutral-v1", "template_version": "4.0.0",
    "geometry_id": "commons-blank-cc0-v1",
    "region_set_id": "commons-blank-cc0-v1-ui-regions-2",
    "atlas_id": "goran-2022",
    "atlas_version": "goran-2022-commons-template4-preview.2",
    "atlas_content_sha256": "8689fca1aa50cff0b1b7d7cd1adcd80cf244cd1a93ed580e91406d0cc2fb2056",
    "body_content_sha256": "59979433be334f53a705f90a484aadc312a426387f4c1a3b59a718393fbf426a",
    "coordinate_system": "normalized_2d_top_left"
  },
  "lesions": [{"id":"synthetic-1","view":"front","source":"manual",
    "vertices":[{"x":0.48,"y":0.32},{"x":0.52,"y":0.32},{"x":0.50,"y":0.35}]}]
}
```

可保存到私有新文件并使用本地 `scripts/evaluate_annotations.py` 从stdin读取，或POST到 `/api/v1/evaluate`。本样例在本次通过Schema与当前图谱核心本地校验，见 `audit/example-evaluate.json`；不是新增医学数据，不代表T节段位置真值。

AI HTTP流程：建立access会话（仅受控测试模式）、建立AI会话→multipart `file`上传→提交定向照片归一化提示→选择candidate→confirm。受控访问每个请求用 `Authorization: Bearer <本次内存会话>`；AI照片另用 `x-ai-session-key: <照片会话key>`，占位符不是可用凭据。不要把token写进命令历史、论文截图或小程序包。准确JSON字段见 `backend/app/schemas/ai.py` 与[API表](05-系统总体架构.md)。

## 6. 独立模型实验复现（历史执行，本次未重跑）

```bash
ai/.venv/bin/python -m ai.cli \
  --image ai/experiments/inputs/cdc-21505.jpg \
  --prompts ai/experiments/example-prompts.json \
  --device cpu --threads 4 --simplify-px 0 \
  --output private-data/reproduction/new-case-001

ai/.venv/bin/python -m ai.experiments.run_suite \
  --device cpu --output private-data/reproduction/new-suite-001

ai/.venv/bin/python -m ai.experiments.oversegmentation \
  --output private-data/reproduction/new-crop-comparison-001
```

输出目录必须新建或为空，脚本拒绝覆盖历史。输入文件可能被Git忽略，不能仅clone后假定存在；按 `ai/experiments/sources.json` 合法获取及 `prepare_inputs.py` 明确派生，校验尺寸和来源。示例提示文件为 `photo_oriented_pixels_v1`，box `[215,245,495,385]`；不得把HTTP的0～1坐标直接传入该像素契约。

CLI默认全图策略，HTTP当前默认context_crop；重现实验必须记录strategy，不能把两者结果混为同配置。suite依cases.json执行9组；oversegmentation记录成对策略与三局部框，21次Predictor调用。需分别保留原图、原Mask、叠加、轮廓、JSON、候选顺序、警告、提示、模型哈希、尺寸、方向和环境。

`segment_image`输出对象含原图、masks与record；export负责写文件。分割状态needs_confirmation不是医学成功。重复实验不能覆盖既有 `docs/validation-records/` 结论，也不能把截图当机器可读原结果。

## 7. 复现常见差异

- EXIF方向、crop offset和长边缩放不是同一变换；先统一方向，所有提示和返回Mask以定向照片为基准。
- 原始照片坐标不可直接传人体接口；需人工放置、完整校验与确认。
- 多片孔洞必须用geometry，不能只用兼容ring；非法拓扑应报错而非静默buffer修复。
- 模型分数、展示优先级与人工确认是不同字段；不能擅自确认最高分。
- macOS MPS冷启动、CPU线程、Linux限制、导出阶段影响耗时；环境变化必须分组报告。
- HTTP临时公网入口不适合患者，release当前没有接入正式服务；旧体验版不会自动获得新配置。
- AI超时工作线程可能尚未停止；不要立即无限排队重试。临时文件会过期，人体几何保存不意味着照片永久保留。
