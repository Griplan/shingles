# V5.3 人工放置 AI 分割轮廓

本文记录 V5.3 的数据合同、实施约束和验证入口；唯一进度台账为根目录 [task.md](../task.md)。V5.2 的模型、上传、候选选择、人工确认与照片安全约束继续适用。人体背景、粗区域、神经图谱及现有视口坐标规则沿用现行版本。

本轮流程为：选择身体部位 → 照片分割并确认 → 放置到人体 → 拖动、调整大小和方向 → 确认位置 → 写入当前 V2 标注会话。人工放置不代表 AI 自动完成了解剖配准；初始位置来自用户选择的粗部位，100% 是编辑基准，不对应照片中病灶的实际物理尺寸。V5.4 的神经匹配整合不在本轮范围。

## 1. 两套坐标与原始结果

V5.2 确认结果 `confirmed-photo-segmentation-v1` 使用 `photo_oriented_normalized_v1`：原点为经 EXIF 方向统一后的照片左上角，`u,v∈[0,1]`；图像宽高为方向修正后的像素数 `W,H`。其原尺寸 Mask、像素指纹、模型信息、提示、候选和 MultiPolygon 各环均保持原值。

人体放置输出使用 `body_template_normalized_v1`，对应完整人体逻辑画布，而不是局部放大框。当前模板为 `commons-neutral-v1 / 4.0.0`，逻辑尺寸 `400×900`，同源轮廓 `commons-blank-cc0-v1`，粗区域修订 `commons-blank-cc0-v1-ui-regions-2`。每份放置结果还必须绑定正/背面、目标模板和 V2 会话身份。照片坐标不能直接传给人体 API。

前端交接只使用运行内存中的不透明草稿 ID。原始确认对象只读；变换参数与变换后的人体几何独立保存，不把照片能力令牌、完整几何或图片内容放进路由 URL。V2 单例仍是正式人体标注唯一权威数据源，放置草稿不是第二份病例集合。

## 2. 相似变换顺序

对照片归一化顶点 `(u,v)`，先还原到同一像素度量空间 `p=(uW,vH)`。整体锚点 `a` 来自所有片区共同的包围范围；平移目标中心 `c=(t_x B_w,t_y B_h)` 使用人体逻辑尺寸 `B_w,B_h`。用统一的逻辑单位/照片像素比例 `k`、大小编辑系数 `s` 和角度 `θ`：

```text
dx = uW - a.x
dy = vH - a.y
xLogical = c.x + k·s·(dx·cosθ - dy·sinθ)
yLogical = c.y + k·s·(dx·sinθ + dy·cosθ)
xBody = xLogical / B_w
yBody = yLogical / B_h
```

X、Y 在同一度量空间先等比缩放/旋转，再分别按人体逻辑宽高归一化。不能直接对照片归一化 X、Y 使用相同倍数后旋转，因为照片长宽比与人体画布长宽比不同。正角遵循画布 Y 向下的顺时针视觉约定。所有独立片区和孔洞共用同一个锚点、平移、比例和角度，不修改片区间相对位置。

屏幕投影复用 `utils/coordinate.ts` 的现有 viewport：全身/聚焦/尺寸变化只改变显示，不修改 `placementTransform` 或正式人体坐标。越出逻辑画布的有限草稿可用于显示和调整，但最终校验拒绝真实越界，不能把投影的裁切当成合法性修复。

## 3. 多片、孔洞与完整包含

照片 `MultiPolygon` 的每个 Polygon 仍包含一个外环及其孔环；相似变换逐顶点保留全部结构，不用凸包、不连片、不抹孔，不因小片而静默删除。Canvas 显示必须与孔洞语义一致，不能用一层实心填充假装支持内孔。正式保存前重新检查坐标、闭环、退化、自交、洞归属和片区拓扑。

人体有效表面使用与当前模型绑定的完整轮廓，不能用人体外接矩形或粗部位区域代替。完整包含至少要验证每条病灶边在人体全部边界交点之间的拓扑区间，并检查填充是否覆盖被包围的背景孔洞。只检查顶点、固定步长取几个边点或先人体裁切后显示都不足以证明合法。

部分越界明确提示“部分病灶范围超出人体，请调整位置或大小。”；完全在人体外同样阻止确认。用户可以继续移动、缩放、旋转；程序不自动裁切、吸附或压缩。病灶自己的孔洞可排除相应背景，判断对象是完整填充区域。数值误差仅用于机器精度边界判定，不是扩大人体表面。

## 4. V2 兼容与提交

旧 V2 手工标注为一个无孔闭环 `ring`，不能用它单独表达 AI 的多片含孔数据。V5.3 保留 `schemaVersion:1` 和旧手工结构，增加可选 `geometry:BodyMultiPolygon` 与 `source`：AI来源为 `{kind:'ai_assisted',placementId,photo,transform}`，其中photo是原只读确认快照的副本，不含会话能力令牌。AI对象的兼容 `ring` 仅为首片外环，不是完整几何；存在geometry时，绘制、命中和序列化必须优先使用完整geometry。手工标注的可选source为manual，旧数据未提供source也继续有效。

拖动和滑杆只更新放置草稿。点击“确认位置”时重新计算几何，检查当前源确认对象/候选、失效时间、目标模板/view、V2 会话 token/revision、完整几何和人体包含，然后一次原子追加。已有手工/AI 标注均保留；失败不得改变原会话。幂等身份防止重复点击或回调重复插入。

一个 AI 贴片作为一个 `completed` 对象写入，内部可以包含多个不连续 Polygon，因而整组只占用一个标注ID；删除整组不会误删其他对象。现行每面20个正式标注对象上限继续有效，不能将它误读为内部只保留20个片区。AI几何总顶点和片区安全上限由准备/校验函数明确检查，超限失败不等于有损截断。

正式追加更新 V2 修订与几何身份，原匹配缓存因此失效。当前 V4 传输契约只支持旧简单环；V5.3 在请求入口明确阻止含 AI 放置几何的会话发出计算，不能偷偷只提交第一片或填掉孔洞，也不修改后端匹配算法。V5.4 需另行扩展传输和后端几何合同后才能无损复用。

## 5. 页面与生命周期

从 AI 页 `navigateTo` 放置页，上一页保留源确认和照片会话。放置按已选正/背面和粗部位聚焦；贴片使用半透明橙红色，拖动不触发人体分区选择或手工加点。小片区通过可见移动控制柄调整；大小、角度滑杆与重置只改当前草稿。放置页本轮不显示神经图谱或计算指标。

自定义“返回照片”在未保存时提供继续调整或放弃本次放置；明确放弃才删除当前放置草稿，不删除 V5.2 原结果或V2其他标注。平台 `enableAlertBeforeUnload` 的实际能力不能当作所有原生返回/手势的强制拦截，因此原生离开路径保留当前运行内的草稿，并在照片页提供继续入口和暂存范围说明。草稿仍受原source有效期约束，不承诺退出/编译后恢复。放置失败时可回照片重新确认候选或重新分析。

原照片/Mask 引用继续受 V5.2 固定 30 分钟会话与取消/换图/退出清理约束。放置期间的源确认对象、session/result/candidate 身份或期限变化会使未提交草稿失效；旧页面和旧拖动回调不能更新新草稿。正式保存的人体坐标是独立的运行内 V2 数据，原图过期不应清掉已保存的人体标注，但不能承诺原 Mask 永久可访问。运行结束或重新编译仍不保证恢复会话。

## 7. 已知边界

MobileSAM 仍可能包含正常皮肤、漏掉可见病灶或产生碎片；应返回照片重新选择，而不是通过人体放置美化错误分割。局部照片没有比例尺，无法由本功能推导真实大小或神经节段。粗部位只是导航上下文，不是定位结论。临床效果、真实患者安全部署、真机与多屏等未执行项目必须单列。

V5.4 需要沿用这里的完整人体几何、来源身份和模板/view 绑定，再设计包含孔洞/多片的请求和匹配兼容；当前不直接调用 V4、不显示神经匹配结果、不更新图谱审核状态。

## 9. 2026-11-01 交互性能增量

放置页现在将编辑预览与正式几何分开。`PlacementPreview`从已确认Mask对应的完整照片轮廓建立一次性透明OffscreenCanvas；移动、缩放和旋转时只维护相似变换并用Canvas变换绘制贴图，最多一个待绘制帧。未支持离屏2D贴图时降级为完整矢量预览，不改变几何。原人体背景保持独立，不增加人体缓存或修改素材。

`PlacementDraft.geometryRevision`标记最后一次结束调整时的完整几何；只有它等于`revision`，这份几何才对应当前变换。移动过程`update(false)`只验证小型变换参数、保留不可变源及最后完成的几何，不再逐事件生成全部顶点。页面不能用旧几何确认。每次操作结束重算和完整检查，确认仍在V2唯一提交入口从原照片重算一次并完整校验；正式标注格式、所有片区/孔洞、V4结果失效和不兼容请求阻止不变。

高频预览通过组件方法传小型参数，不使用每事件setData；百分比/角度文字每100ms最多更新一次，结束即时同步。触摸位置每次手势开始重新测量，同一手势共享；滚动、视口改变、隐藏和退出取消旧输入/帧，隐藏/卸载前收尾未完成调整。临时贴图只在内存，源变更或组件卸载释放，无文件导出或新增上传。

贴图上限2048像素长边，编辑中的放大预览可能有栅格插值；停止调整后绘制全部原顶点的精确矢量轮廓，保存从不读取或降采样贴图。2000点完整校验仍约0.2秒，本轮未重构包含算法。详见[同环境对照及真实验证记录](validation-records/v5.3-performance/report.md)；原生流畅度和真机仍须单独验收，不能把JS适配计时当作FPS。

## 10. V5.4 确认计算与已保存标注重放置（2026-11-01）

本节覆盖上文“不进入 V4”的历史阶段边界。主按钮变为“确认位置并计算”：原完整几何/人体面校验和原子提交成功后，才通过原 matchingSession 调用 evaluate；所有片区及孔洞完整传递。请求失败只重试计算，不重新插入。原 V5.3 拖动贴图、单帧调度、局部参数更新与最终验证路径保留，无拖动网络请求或每帧全量几何变换。

结果页可调整已保存的 AI 标注。重新放置从只读原 source 和原变换创建草稿，调整/放弃不修改原正式几何。确认时核对旧 placementId 并原位替换，annotation ID 稳定、revision 增长、新 placementId 令旧匹配失效；其他人工/AI 标注不变。原照片到期后仍可对正式人体几何匹配，并使用内存快照重放置；不延长或复活照片。

跨页只传一次 session/response 关联的显示相机，保留 view、focus、CSS 缩放及画布中心对应的位置；几何坐标不因显示容器改变。结果继续复用 V4 全量高亮与侧栏。数据契约、边界和验收见 [V5.4](v5-ai-integration.md) 与 [本轮记录](validation-records/v5.4/report.md)。
