# 医审边界到V4几何匹配的接入方案

这是后续可实施的技术设计；本轮不修改加载器、不新增运行区域、不启用计算。

## 1. 接收什么才足够

必须先接收可追溯的边界包：固定模板/侧别、边界源作者及许可、原图页码或路径、审核人/角色/日期/范围、逐条闭合曲线或签署的带坐标图、不确定/排除面及批准范围。仅有感觉点、ICBN图、口头节段名称或勾选“图看起来正确”不满足准入。

`review-draft/boundary-submission.template.json` 刻意把 geometry、label、approval 留为null；它不符合运行atlas格式，也不会被运行服务加载。未来填完后仍先在审核资料目录验证，不能因为文件名含approved便复制入生产目录。

边界审核通过状态应为独立记录 `boundaryReview.decision=approved`，附签署文件的摘要。它仅批准指定版本的参考边界，不等于系统整体医学审核或正式发布权限。

## 2. 统一坐标和模板版本

优先在本目录400×360原比例SVG底板上绘制。应用所有SVG父变换后，逻辑点 `(X,Y)` 转为 `(X/400,Y/360)`，原点左上。若审核的是新模板B，则使用其正式批准宽高和新identity，不能继续除以400/360。

图01/02的主体窗口位于审核板 `(50,190)`，尺寸780×702，保持400:360。若审核者只能在这张板上标注，先扣去窗口偏移：`u=(boardX-50)/780, v=(boardY-190)/702`，并验证没有取到旁注/下方Goran窗口。扫描或截图有额外缩放、旋转时，必须先用板角/刻度恢复坐标，保存重投影误差；不能猜测截图像素。

本轮手画观察窗口的坐标为 `review_template_normalized_v1`，不得自动改名为人体坐标。只有经审核的最终边界、有效性检查和版本绑定完成后，才可输出现有图谱的 `normalized_2d_top_left` 几何及V2使用的 `body_template_normalized_v1` 标注空间。照片空间始终无关。

源图跨姿态配准另行处理：可见的**同一皮面**至少需要分布合理且非共线的控制点、独立检查点和配准误差。相似/仿射拟合只能描述已验证范围，不能恢复遮挡面；若需要非刚性变换，须单独审查其形变和目标边界，而不是默认启用。新表面需要新证据或专业人员在目标底板上直接审核绘制。左/右分别建立记录。

## 3. 曲线转Polygon/MultiPolygon

复用 `scripts/svg_geometry.py` 解析/采样思想与现有Shapely工具，不建立另一套在线匹配算法。离线步骤：

1. 锁定源SVG、viewBox、层ID、父变换、fill-rule、clip/mask和许可。未知mask不能忽略；先解析或显式阻塞。
2. 闭合外环、内环；保留多个离散片区及孔洞。轮廓嵌套和填充规则共同决定孔洞，不能只看顺/逆时针或用凸包合并。
3. 在**逻辑像素**度量中自适应采样，分别保存原曲线和输出几何。初始技术采样上限可设0.2逻辑像素（待实际曲率/放大验证），它不是医学误差容许值；不自动删小片区、做闭运算或无记录简化。
4. 检查有限数值、0–1范围、闭合、面积非零、无自交、洞在外环内、片区关系、人体轮廓完整包含。默认拒绝无效几何；不能静默 `buffer(0)` 或 `make_valid` 改形后称医审通过。
5. 量化采样前后面积差、Hausdorff距离、片区数/孔洞数；对所有边界叠加回批准底板，让审核者确认转录无损于其意图。数字化误差和医学不确定性分别记录。
6. 不确定范围不自动归最近节段。相邻分区应共享明确边线；若来源表示真实重叠，保留并说明，不为强制互斥改写医学来源。

## 4. 正式数据身份与文件落点（后续实施）

每个区域至少写入：`id, view/viewId, side, templateId, templateVersion, geometryId, regionSetId, atlasId, atlasVersion, partitionType=spinal_dermatome, labelId, dermatomeLabel, sourceLabel, geometry, sourceRefs, sourceFile, sourceElementId或sourceElementRoute, sourcePathSHA256, sourceLicense, registrationMethod, boundaryReviewRef, medicalReviewStatus`。

`geometry` 复用现有局部图谱的GeoJSON式 Polygon/MultiPolygon数组，不能把审核窗口当region。源元素没有id时保留null并用route+hash，不能伪造SVG id。组合标签按来源保留。

沿用独立 `axilla-left/right`，不能写到front/back/sole或把不同视图面积相加。若显示几何未变，仅创建新的 **atlasVersion及内容摘要**；若底图变，必须新templateVersion/geometryId并隔离旧标注。旧结果按已有identity/revision检查失效；旧标注不删除，旧atlas身份不能悄悄改成新结果。

未来需同步的现有文件：

- `data/atlas/axilla-v1/` 的左右regions、sources、registration、manifest；新增独立、可回溯的边界审核记录，不覆盖本轮空图谱历史证据。
- `backend/app/services/axilla_atlas_service.py` 的版本及绑定；继续复用 `local_atlas_service.py`、`atlas_service.py` 和现有V4求交/并集、P6缓存。无需新的腋下求交公式。
- `scripts/build_axilla.py` 的离线生成职责，以及 `miniprogram/data/axilla.generated.ts` 的identity、regions和technicalReady；不是手工修改多个UI分支。
- 局部页面继续使用 `pages/local-surface`、`components/local-surface-canvas` 和 `state/local-surface-*`；若审核状态类型扩展，同步 `types/local-surface.ts`、API/schema与测试。原标注会话仍是唯一数据源。

## 5. 当前加载器的实际门禁——不能仅改一个true

已检查 `backend/app/services/local_atlas_service.py`：

- 目前仅允许 `mappingEnabled=false`、`medicalReviewStatus=pending` 的参考预览语义。直接把manifest改成approved/true，会因preview gate失败返回503，**不会自动成为正式医疗匹配**。
- 参考几何加载还要求 `technicalValidationStatus=passed_offline_geometry`、`sourceLicenseStatus=verified`、boundarySystem=spinal_dermatome、有效边界来源、双侧非空、完整identity/hash和皮肤内包含。
- 本轮仍为blocked_missing_boundary_evidence、0区域，正确返回409 ATLAS_NOT_READY。

推荐后续第一步只接入**通过边界审核的研究/教学参考几何**：单独保留真实 `boundaryReview` 已审核记录，系统级manifest仍表达未完成整体医学验证，保持正式映射关闭，并明确两种审核范围。若需要将系统级状态也表达为approved，必须另行授权修改状态合同、前后端类型和门禁测试，不可静默篡改pending的意义。

当前加载器要求左右都有区域；若只有一侧有可靠证据，保持阻塞，或另行实施显式逐视图就绪机制。不得镜像、复制或伪造另一侧区域来通过检查。

## 6. 后续验证与启用顺序

先模板/来源审核 → 边界签署 → 离线数字化 → 叠加回审 → 数据版本发布 → 后端/前端同步 → 受控参考匹配验证。缺一项不启用。

技术验收需覆盖：两侧标签/方向；单区、跨区、多片/孔洞；仅接触边界；未配置皮面；旧版本拒绝；高亮和几何同源；左右/全身/足底会话隔离；V2标注兼容；V4去重覆盖、未覆盖比例和P6性能。不能用由命中函数自动产生的点充当独立医学参考点。

非空但部分覆盖的已就绪图谱可沿用V4未覆盖计算；**空/未审核图谱必须保持ATLAS_NOT_READY，不能伪装成“计算成功但未覆盖100%”**。既有V4公式不变，几何重叠结果依然不是临床诊断。

本轮到审核包与接入设计为止；没有发布新atlas、运行生产服务或上传体验版。
