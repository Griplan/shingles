# 人体放置入口等待专项审查

## 结论

“正在准备人体轮廓”不是单纯加载一张图片。它需要把照片坐标中的多片轮廓复制到独立放置草稿，校验闭合环、孔洞、自交与多片关系，执行相似变换，再逐边及填充区域检查是否位于人体内。进入放置页后还要等待人体首帧、Canvas 尺寸和离屏病灶贴图完成，之后才能安全启用“确认位置”。

正常手机照片确认出的轮廓通常远少于 2,000 点，真实瓶颈不应表现为长时间等待。本轮对一个 2,000 点、5 片、5 孔的同源生产几何流程实测：本机入口几何准备由 43.5 ms 降到 5.4 ms，`PlacementSessionStore.open()` 连同复制、冻结和目标会话建立约 6.8 ms。

## 实际步骤

1. 校验照片坐标、闭合范围、孔洞、多片、自交、重叠与 20,000 点上限。
2. 计算照片包围盒和初始缩放中心。
3. 对整个 MultiPolygon 应用一次等比缩放、旋转和平移。
4. 对变换后的完整填充区域、每条边和人体孔洞执行边界检查。
5. 复制并冻结独立放置草稿，建立 V2 目标会话。
6. 跳转到放置页，加载正常人体资源并测量 Canvas。
7. 生成一次离屏病灶贴图，绘制人体和病灶首帧。
8. 首帧发出当前 revision 与 viewport 对应的就绪事件后，才启用确认按钮。
9. 就绪后才异步删除后端照片会话，因此 DELETE 网络耗时不在入口等待内。

第 1、3、4 步都涉及全部顶点；第 6、7 步受手机图片解码、Canvas 首帧和原生桥影响。此前后端照片删除已被移到首帧就绪之后，不会阻塞放置。

## 优化

- 人体轮廓按 Y 轴分桶缓存，每条病灶边只检查可能相交的人体边界候选；最终仍调用原来的精确 `pointInBody()`。
- 多片孔洞的边比较、空洞包含、接触和片区重叠检查增加 Y 轴保守候选索引，保留原 EPS、边界接触、孔洞与面积规则。
- `polygonInterior()` 改为扫描线活动边处理，避免对每个扫描高度重复遍历全部边。
- AI 页面在同步几何计算前立即显示“正在准备人体轮廓”，并在下一次事件循环后再开始计算。
- 放置页在人体与病灶首帧稳定前显示“正在加载人体与病灶范围…”，避免出现可点击但内容尚未稳定的状态。

## 同数据对照

环境为 Apple M4、Node.js 24.11.1。以下为 5 片、每片 1 孔的生产几何模块中位耗时，不代表手机原生耗时。

| 总顶点 | 优化前总耗时 | 优化后总耗时 |
|---:|---:|---:|
| 100 | 1.08 ms | 0.92 ms |
| 500 | 5.46 ms | 1.92 ms |
| 2,000 | 43.53 ms | 5.39 ms |
| 5,000 | 220.83 ms | 13.92 ms |
| 10,000 | 861.24 ms | 26.64 ms |
| 20,000 | 3,168.15 ms | 61.04 ms |

完整 `PlacementSessionStore.open()` 在 2,000、10,000、20,000 点时分别约 6.76、29.96、64.70 ms。原始数据见 `evidence/benchmark.json`。
