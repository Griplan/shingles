## 最小实现调整

- 原照片坐标几何继续不可变。源Mask已在V5.1无损导出为照片MultiPolygon；用这份已确认的完整轮廓一次性生成透明离屏贴片，避免重新下载带权限的Mask或创建新的分割实现。不会修改Mask、简化顶点、桥接片区或填孔。
- 新`preview.ts`缓存照片像素路径和一张2D OffscreenCanvas。贴图长边含留白不超过2048像素（最多约16MiB RGBA，未包含平台额外开销）。仅编辑预览使用位图；结束时恢复所有顶点的精确矢量填充/细描边。低分辨率缓存不作为保存数据。
- 拖动和滑杆changing只更新小型变换参数，直接交给本地组件；不通过setData传MultiPolygon。百分比和角度文字最多每100ms刷新，结束立即同步。移动中没有完整顶点变换、拓扑或人体包含校验。
- 每个Canvas最多一个待绘制requestAnimationFrame；不支持时使用可取消的16ms单次定时器。没有常驻循环。多个事件只保留最新变换，背景稳定。Canvas上下文只取一次，尺寸只在变化时设置。
- client坐标每手势开始测量一次；移动和结束共享该测量。滚动/视口/来源/禁用/隐藏/卸载取消旧手势或旧帧，重新开始时重新测量。异步start/end仍严格按派发顺序。
- `geometryRevision`明确区分最后一次完成的几何与正在移动的参数。操作未收尾时禁止确认旧几何；结束后重算并完整校验，重复同值结束事件不重复校验。确认仍在V2唯一写入口从原始照片几何重算一次并完整校验，再原子追加；不信任缓存位图或旧校验。
- 卸载/隐藏时保留最后变换并收尾，取消文字定时器；卸载或更换源释放贴图缓存。Offscreen不支持、创建失败、drawImage失败时降级为全部矢量路径，并保留帧合并/状态优化。

兼容依据：项目已有官方`miniprogram-api-typings@5.2.3`声明2D Canvas的requestAnimationFrame/cancelAnimationFrame、createOffscreenCanvas({type:"2d"})及drawImage(OffscreenCanvas)。[微信官方类型来源](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.canvas.d.ts)。官方网页访问失败，未用第三方资料代替能力验证；真实设备兼容仍需下述原生复测。

### 原生计时与连续绘制

为避免把测试适配器当成微信画布，本次在实际运行的页面/组件安装临时转发计时包装，只记录计数/耗时和几何数量，不打印照片内容、会话密钥或完整坐标。计时包装已恢复；脚本存于 `native/probe.js.txt`。

第一次使用 `wx.getPerformance().now()` 得到非单调样本、少量负耗时，且逐lineTo计时有明显探针开销，故**该轮耗时废弃**，保留 `initial-wx-clock-metrics.txt`。随后使用模拟器控制台 `performance.now()`，移除逐顶点绘制计时。一次只读数量诊断误用 `p.holes.length`（实际是环数组）产生1条控制台异常，修正为 `p.length-1` 后得到上述数量；没有因此改动产品或把控制台写成Errors0。

实际工具drag只派发1次move，随后end在下一绘制帧之前到达：该轮只观察到最终精确矢量绘制，不能声称测到了连续拖动缓存。因此另通过控制台**显式回放**组件触摸处理器60次move（每次间隔20ms），以及各40次连续缩放/旋转事件，仍使用真实微信Canvas、实际MobileSAM轮廓和现有生产处理器。回放不等于人手触摸，也不作为真实触摸采样率证据。代码和原始结果均保留。
