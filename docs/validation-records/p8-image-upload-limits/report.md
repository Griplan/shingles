# P8 高清手机照片自动适配

日期：2026-11-09。状态：本地实现、真实本机推理/放置、自动回归通过；桌面微信完整交互、手机体验版和线上复测尚未完成。

## 限制来源及本轮修改

| 层 | 核查结果 |
| --- | --- |
| 旧小程序页面 | `wx.chooseMedia` 选择原图，再按选择器报告的字节数预检查。trial/受控环境超 10 MiB 就拒绝；原来未按像素自动缩图。 |
| 旧小程序上传层 | `wx.uploadFile` 直接发送选择的原图；原先把后端 `IMAGE_TOO_LARGE` 和 `INVALID_DIMENSIONS` 映射成同一条 10 MiB / 300 万像素提示。 |
| 微信平台 | 微信团队的[大文件上传库](https://github.com/wechat-miniprogram/miniprogram-file-uploader)记录过 `wx.uploadFile` 单文件 10M 限制；本轮未在手机实测版本上限。P8 采用 8 MiB 客户端硬上限，不引入分块上传。 |
| 云端 Nginx | 实际 `nginx -T` 核查：公网测试 API 路由请求体 11 MiB（含 multipart），其所在 IP 站点一般默认 10 MiB。测试 API 仍按 IP 5 次/秒、突发 12、同时连接 6。 |
| FastAPI 受控模式 | 10 MiB 实际照片；请求体上限为照片限制加 64 KiB。流式收集请求体时超过上限即返回 413，路由 multipart 解析后在会话层再次检查实际文件。独立开发配置为 20 MiB / 1200 万像素，仍受各自后端约束。 |
| Pillow | 受控模式按 JPEG/PNG/WebP 实际格式和帧数验证，8–8192 像素/边、总计 ≤300 万像素。打开图片后、展开像素前核查宽高，保留解压缩炸弹防护及 EXIF 方向修正。 |
| MobileSAM | 从服务端方向统一的 PNG 重新解码，每次分割读一次，不重用上传时的常驻 RGB；推理最长边缩到 1024，再补边至 1024×1024，结果还原到上传处理图。模型单并发；受控配置 PyTorch CPU 1 线程，AI 写请求边界同时最多 2，最多 2 个临时照片会话。 |

腾讯云只读结果：4 个逻辑 CPU、总 RAM 3723 MiB，巡检时 available 2339 MiB，swap 1987 MiB 且使用 0。智络智绘服务 active，单主进程，CPU 配额 1 核、MemoryMax 1536 MiB，采样 MemoryCurrent 约 515 MiB；另一次主进程 RSS 约 605 MiB，采样口径和时间不同，均不是推理峰值。针灸和 Nginx 同时为 active。首次只读源码命令因远程无 `rg` 未读到文件，用 `grep` 复查成功。未向腾讯云上传样图或施加负载。

## 图片准备和坐标

- 相册和拍照走同一准备流程。读取文件实际字节数、文件头和微信返回的原始轴宽高；本地上限 **20 MiB、1600 万像素、单边 8192**，任何一个超限都会给出相册裁剪提示，避免在小程序里强行解码更大的照片。
- 上传上限 **8 MiB、300 万像素、最长边 1920**。按比例缩小并向下取整；4032×3024 → 1920×1440（276.48 万像素）。小图符合所有条件时直传。需处理的图片用 Canvas 2D 编码成 JPEG，先用质量 94；不合格时从同一解码原图重新编码，逐步降低质量，必要时再缩小，不串联重复压缩、不自动裁切。
- 支持设备可解码的静态 JPEG、PNG、WebP；纯 HEIC/其他不支持格式提示在相册转存。PNG/WebP 转码时以白底合成，与后端一致；动图不会作为静态照片进入推理（需转码时客户端拒绝，直传时后端校验帧数）。非默认 EXIF 方向时，转码前移除源图方向元数据，按对应旋转或镜像矩阵绘制一次，并验证输出为正向且宽高符合计划。未经转码的小图继续由服务端统一方向。
- 页面显示“正在准备照片”“正在上传”“正在 AI 分析”和“AI 分析完成”。取消或退出后，过时的准备结果不进入上传；自建解码副本、转码结果在成功/失败/取消后释放。异常退出残留的自建解码副本在再次打开 AI 页面时检查并清理超过 5 分钟的文件。服务端收到断开连接而尚未收齐请求体时停止读取；已经开始的上传或推理可能继续短时间运行，现有代次校验、会话删除和 30 分钟 TTL 保留，不声称立即终止原生网络请求或推理线程。
- 后端定向后的**处理图**是唯一坐标参考。预览、正负提示点、框、Mask 和轮廓使用同一个宽高及 `photo_oriented_normalized_v1` 空间。原始文件尺寸只用于本地缩放，不进入 API，也不宣称坐标能直接回到原始文件像素。人体放置使用处理图的正确宽高比，输出仍是 `body_template_normalized_v1`；未修改几何算法。

## 实测与限制

| 样例 | 处理前 → 后（字节） | 准备到请求发出 | 本机上传 HTTP | 分割 HTTP，两次 |
| --- | --- | ---: | ---: | --- |
| 4032×3024 正向 | 1,266,413 → 333,423 | 195 ms | 150 ms | 0.786 / 0.739 s |
| 存储 3024×4032，EXIF 6，视觉 4032×3024 | 1,283,908 → 333,555 | 237 ms | 151 ms | 0.780 / 0.747 s |

本机测试使用公开 CDC PHIL 21505 放大和填边制作测试尺寸，不是新的临床样本。运行实际小程序页面、组件和会话代码，以 Node/Pillow 适配微信接口，发送真实 HTTP 给本机 MobileSAM。两例均完成框选、自动推理、候选切换、正负点细化、确认、人体放置/旋转、两次匹配以及已有人工标注保留。照片与 Mask 同一绘制矩形，框选数值往返最大偏差约 1.6e-13 个处理图像素；两个最终确认的 MultiPolygon 按像素中心重建，与各自 Mask 的差异均为 **0 像素**。分别保留 4 片/19 孔与 8 片/16 孔，放置后数量不变；两例删除后照片访问 HTTP 410。数值验证不是手机触摸误差或医学准确率。

另在同一开发机隔离运行受控限制、CPU 1 线程：Pillow 解码、定向、转 RGB 26.6 ms；包含写入会话 PNG 的上传服务处理 156.5 ms。真实 MobileSAM 编解码 0.861 s，含几何约 1.012 s；包含冷加载、PNG 重新解码及产物写入的分割服务总耗时 2.628 s。进程累计峰值 RSS 在上传前、上传后、分割后分别为 157.5、205.6、870.5 MiB（首值包含生成测试图，非分阶段增量）；不能外推为腾讯云或手机峰值。原始 4032×3024 在受控模式拒绝为 422，超过 10 MiB 的实际文件拒绝为 413，临时上传文件及会话已清理。

测试还覆盖 1000×1000、1920×1080、3000×2000、4032×3024 及其竖向版本、4000×4000、超 1600 万像素、小字节高像素和高字节低像素、8 种 EXIF 变换、错误格式及取消。真实 Pillow 测试核实 JPEG/PNG/WebP、损坏的 JPEG 头；真实 1920×1440 合成高噪声 PNG 有 11,064,199 字节、原后端拒绝，等效白底 JPEG 重新编码后 2,806,473 字节、同尺寸通过。该 PNG 编码由 Pillow 适配证明，不冒充微信真机编码。
