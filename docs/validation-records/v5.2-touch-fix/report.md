# V5.2 松手未触发识别：修复与验证（2026-10-28）

## 用户反馈与复现

用户实际反馈“松手后没有变化”。此前完整原生流程的待验结论由此补充为一次失败反馈，不再将它仅归因于自动工具拖动限制。

检查发现两处确定的前端缺陷，并通过回归测试复现：

1. `point()` 等待微信异步 `boundingClientRect` 后，用画布重绘序号判断坐标是否过期。连续派发 move/end 时，先完成的 move 引发 redraw，仍在等待的 end 就被判过期，返回 null，最终没有提交框、没有请求或提示。旧测试依次 await 每个事件，因此没有覆盖这种时序。
2. `mode,disabled` observer 不检查值是否实际变化，每次通知都清空拖动起点；同值通知也会中断有效手势。补充测试在拖动中发送同值通知即可复现。

修复前新增3项测试中2项失败（共201项，199通过），详见 `before.txt`。取消时序测试作为保护用例原本通过，不算新发现的失败。

当前尚未捕获用户此次原生事件的完整轨迹，不能断言这两处缺陷就是该次操作的全部原因；原生最终结论仍需修复后复测。

## 修复

- 照片画布将“重绘序号”和“手势有效期”分开；同一照片重绘不再作废有效触摸。
- 在原生事件到达时启动坐标查询，按事件派发顺序处理查询结果。即使查询回调乱序，start/move/end 也不会颠倒；重复松手不会重复提交。
- 仅在实际换照片、尺寸/布局、模式/禁用状态变化、取消或新手势时失效旧手势。同值属性通知保留当前起点；旧照片和取消后的异步回调不能复活手势。
- 保留原来的照片归一化坐标、显示变换、最小框阈值、一次自动请求与候选人工确认逻辑。MobileSAM、FastAPI、V1～V4和正式人体图谱均未改。
