# V4 连续操作与体验精修

2026-10-26～27。本文说明当前实现；唯一总进度见 [task.md](../task.md)。此前 [交互版](v4-interaction.md) 的独立结果路由和“显示全部自动复位”是历史行为，本轮改为同页展示并保留视野。工程实现、模拟器功能证据、动态视觉和真机验收分别记录。

## 已确认的原实现问题

1. annotate 的“计算”通过 navigateTo 进入 result；两页分别创建人体组件、初始化结果页视口。复核状态还会清除入口聚焦，造成用户视野变化。
2. body-canvas 每次属性更新均重新测量节点并获取上下文，即使只是单区/全部切换；图片未就绪分支会先 clearRect 再等待异步加载。
3. 旧组件已经按资源地址缓存图片，Canvas 宽高也已有相等检查。因此不能声称它每次点击都解码 PNG 或重置 backing-store；真正改进是跨流程复用同一节点、预加载两个视图、避免无效测量和空白等待。
4. 独立结果页带入侧栏和结果控件，标注页与结果页容器不一致；旧显示全部操作同时清除 focus。透明度过渡不存在，候选直接替换。
5. 本轮真实 GUI 发现说明弹层被原生 Canvas 覆盖。已复用原有 interactionBlocked/hidden 方案：说明期间隐藏像素层并阻止触摸，保留节点、视口和缓存，关闭后完整重绘。不是 wx:if 销毁画布。

原组件快照与可复现计数见 [对照记录](validation-records/v4-experience/canvas-counters.json)。没有优化前真实录屏或 FPS 基线，不把代码推断当作流畅度实测。

## 当前操作

- 在同一个 annotate 页面圈选、闭合、复核、计算、看结果和返回修改。闭合即单次半透明病灶填色；等待或失败保留填色，结果显示后保留棕色轮廓。
- “计算”只请求一次，通过身份及修订核验后默认显示所有实际匹配实例。没有进入结果页后二次计算。旧 result 路由仅兼容跳回 annotate；无缓存时仍由用户点击计算，不在 onShow 自动请求。
- 侧栏始终预留宽度。点击标签只改变选区，显示全部、逐片筛选、复核和返回修改均不自动复位；“全身”和“放大当前”才主动改变当前视野。换面使用该面的独立状态，不将正面的聚焦框套给背面。
- 主界面保留正背面、逐片/汇总、画布与两侧标签、必要图例、当前主要操作和一行“参考图谱对应，非诊断结果”。错误、未覆盖、部分覆盖、失效仍显示。
- 颜色、间距和圆角集中于页面样式；覆盖层 200ms、控件反馈 120ms 在 experience 配置中。标签高44px，拥挤时独立滚动；短屏允许整页滚动，不拉伸人体。

## 绘制与竞争保护

body-canvas 的 WeakMap 保存节点、上下文、布局测量、本地图片和当前透明度。只在初始、页面恢复或真实布局变化时测量；仅尺寸/DPR变化时改物理宽高。按模板版本、view及资源路径缓存、预加载两张人体图。资源就绪前保留旧完整场景；一帧内同步完成清理→人体→参考区域→病灶→调试，清理之后没有异步等待。

matching-presentation 以不可变候选数组、几何来源和视图缓存实例映射，保持稳定 ID、完整 MultiPolygon/孔洞/真实颜色。atlas-render 按原始区域对象和最近视口缓存投影点；没有新的面积算法或病灶到参考区域的形变。

覆盖层使用微信 Canvas 节点 requestAnimationFrame/cancelAnimationFrame，OverlayTransition 从已显示透明度继续。相同实例保持，其他实例淡入/淡出；后来的选择替代旧任务，结束即停。无帧能力或“减少动态效果”时直接显示正确终态。标签仅在实际第一帧和视口事件之后显现，不用固定延时猜资源加载；每帧不 setData、不重算标签布局。

网络沿用 matchingSession 几何快照和请求序号；页面另核对生命周期与请求编号。场景身份包含会话、响应、view、scope、修订、选区、显示模式及聚焦/动效状态。组件 generation 与 transition serial 拒绝旧回调；换面先等目标本地图片，再提交整套标注/候选/侧别。隐藏、卸载、弹层和换面准备期间清理或禁止旧输入。几何改变立即移除旧结果；未改几何可复用缓存。说明关闭的同场景重绘不会把刚完成的过渡耗时覆盖成几毫秒。

同一 Canvas 透明度动画仍会重绘人体底图；本轮没有增加离屏缓冲或逐区域大画布。提前载入两张本地图片会增加初始驻留内存。真机帧率和内存峰值尚未测量。
