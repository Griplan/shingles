# V5.1：独立 AI 提示分割可行性报告

日期：2026-10-27。当前进度以 [task.md](../task.md) 为准。本报告记录真实本机实验；没有修改小程序、人体坐标、图谱、匹配接口或后端环境。

**结论：工程链路可运行，医学图像的分割质量不稳定，只能作为用户确认的候选。** MobileSAM 可加载、CPU/MPS 真推理、输出对齐 Mask、透明叠加图及保留多片/孔洞的照片轮廓。框选清晰簇状区域可获得有用候选；单点常只选一个小目标，多前景点会产生几乎整张图的错误候选，背景排除也不能保证消除所有错误。不能直接按最高模型分数接受结果。未证明临床准确性，未开始 V5.2。

## 4. 实现与数据契约

`ai.inference.mobile_sam.MobileSAM` → `segment_image(image,prompts,model=...)` → `export_result(...)`。接收本地文件，统一EXIF方向、RGB/透明白底；提示基于校正后的原图像素。模型自身ResizeLongestSide至1024并补边，官方postprocess回原图；保存原尺寸、方向、resized/padded尺寸，强制检查Mask维度。输出预览不继承EXIF、GPS或文件名。

每个结果包含：schema_version、UUID result_id、时间、原/方向校正后宽高、方向处理策略、校正RGB指纹、模型版本和权重哈希、原提示、模型变换、候选、Mask本地引用、耗时、环境、status/error。`requires_user_confirmation=true`，没有任何自动confirmed状态。

- 输入basis：`photo_oriented_pixels_v1`，点 `[x,y,0|1]`，框`[x0,y0,x1,y1]`。无前景点且无框、非法类型/非有限/超界明确拒绝。
- 输出basis：`photo_oriented_normalized_v1`；左上原点、x右/y下；像素格边缘除以原图width/height。`MultiPolygon.coordinates[片][外环或孔][闭合点][x,y]`。无需猜测人体左右、部位或节段。
- 有效候选status=`ok`；整体=`needs_confirmation`。空Mask=`empty_mask`；转换失败=`contour_failed`或`partial_failure`，保留原Mask和明确error；加载/输入等失败CLI写failure.json且非零退出。
- 三个候选是备选分割，不是三个可相加病灶。`model_score`是SAM内部预测Mask IoU，甚至可能>1；不是经校准概率或医学置信度，不截断伪装、不自动按分数确认。

Mask转轮廓将每行连续像素建成像素格矩形，再取几何并集，四邻接，不连凸包、不填孔、不删小片。默认简化0；可配置像素简化容差，但只接受与原几何完全等价的结果，否则显式记录回退。超过100,000行片段或几何错误返回失败；不静默删片。外环/孔方向相反、显式闭合，边缘可到归一化1。保存实际候选几何可能远超128点，后续必须明确处理，不能直接传现有V4接口。

独立CLI的安装、使用和错误码见 [AI README](../ai/README.md)。每次新的私有输出目录包含原图、提示、三个候选Mask、透明层、叠加、轮廓、JSON。实验期间没有照片上传、HTTP服务、数据库、训练或新Web界面。

## 6. 性能和资源

主CPU实验，4线程float32：模型加载1.556s；9次推理0.432～0.681s，中位0.441s；含图像准备/轮廓的总处理0.453～0.898s（不含磁盘预览导出）；进程峰值RSS约920MiB。CPU时间为进程各线程累计秒数，详见原始记录，不冒充整机利用率。

MPS首次实际调用5.915s（编码2.600/解码3.316），总处理5.962s，保留冷启动成本。之后另开实例，受系统着色器缓存影响，首次0.438s；同实例三次预热0.118～0.126s。对应CPU控制实验预热0.423～0.427s。MPS进程峰值约512MiB，完成预测/清理图像后张量约45MiB、驱动分配读数最高约1.45GiB（仅各次完成后采样）；统一内存，不把这些简单相加称显存峰值。GPU利用率 **NOT_MEASURED**。MPS和CPU同一框选三个Mask逐像素一致（这不是跨所有设备/输入的数值保证）。

默认CPU保证无GPU环境可用，支持显式`--device mps`；不静默回退。在本机MPS可降低预热后延迟，部署设备速度需要另验。资料：[主CPU日志](validation-records/v5.1/inference-cpu.txt)、[首次MPS](validation-records/v5.1/inference-mps.txt)、[CPU控制](validation-records/v5.1/benchmark-cpu.json)、[MPS控制](validation-records/v5.1/benchmark-mps.json)。

## 8. V5.2准备与后续风险（仅设计）

建议小程序未来经`wx.uploadFile`把获准照片送到自有后端的独立可选AI入口；由服务器先统一方向，返回不含EXIF的预览ID/宽高，用户在同一预览上给提示。再提交photo_id+photo像素提示，返回本模块候选JSON和受控Mask/预览引用。需要单独的“用户确认候选”操作，上传/推理/确认/删除可分别设计为接口；**目前一个也没有实现**，不能直接调用现有evaluate上传照片。

V5.2需限定尺寸/并发、生命周期、清理、超时、权限、日志脱敏和模型复用；官方Predictor状态不能被并发请求共享。需真实标注集及专家/用户观察来评估提示轮次、漏选/过选和失败拒绝。正常皮肤或低对比下也会返回Mask，产品必须允许拒绝并回到手工流程。

V5.3才定义人工平移/等比缩放/旋转、模板版本/view和独立的照片到人体变换，明确孔洞/多片/顶点上限策略。不能从照片猜部位或神经节段。V5.4才进入原V4几何接口；V5.5做完整验收。本轮止于候选分割预览，等待用户审查效果。

样本分辨率补充：本次使用CDC官方低分辨率JPEG下载入口，未下载18～25MB高清源文件；“原图尺寸”指本次输入文件尺寸。近照与远照/裁片的细节差异会影响结果，不能据此推定高清手机照片的表现。

## 9. V5.2 小程序与本地服务（2026-10-27）

本节为V5.2增量，保留以上V5.1全部结论。已实现部位入口 → 用途说明 → 上传/相机选择入口 → 已定向照片 → 默认矩形框 → 真实多候选 → 切换/补充前景和排除点/撤销/重置 → 显式确认 → 照片确认页。返回仍有原手动流程。相机入口有实现，但实际拍摄未测。确认不进入人体配准或神经匹配；最高分不自动确认，也不在UI展示为医学准确率。

模型完全复用V5.1 MobileSAM vit_t、官方固定commit和40,728,226字节权重；不训练、不重下、不引入付费API。适配器在进程内懒加载并复用模型，串行Predictor；本轮本地HTTP和微信实测CPU4线程。AI依赖与可选服务依赖只装ai/.venv，核心backend/.venv无新增包。默认生产关闭，前端真机/非develop关闭；正式患者上传尚不具备部署条件。

照片按EXIF统一方向且剥离元数据后返回PNG；触摸和Mask共享等比显示矩形，留白排除，DPR不进入照片坐标。归一化提示乘处理后原图尺寸后交给现有模型；模型原尺寸Mask经既有精确轮廓算法输出闭合MultiPolygon，保留孔洞/碎片。没有裁超框Mask或美化假候选。过大/超框/过碎/相似候选只提示，空/轮廓失败不能确认。

前端隔离照片generation、提示revision、推理request_id和预览serial；换图、改提示、切候选、取消及迟到返回不会确认旧Mask。确认绑定照片像素SHA/尺寸/结果ID/候选ID/修订。后端的独立会话能力令牌、受控素材下载、大小/像素/并发限制、TTL与退出清理见[接口](api.md#v52-临时照片分割接口2026-10-27)、[隐私](privacy.md#9-v52-临时照片的实际生命周期)。确认结果只暂存，离开即清理，不是病例存档。

## 10. V5.2 极简交互增量（2026-10-28）

默认预览按源顺序第一个status=ok的真实候选，不按模型分数排序；“换个结果”循环可用候选，不再触发推理，不确认。空/轮廓失败候选不作为可确认选项，完整原始记录仍保留在原服务；如果全部不可用，显示“这次没有得到合适的识别范围，请重新圈选。”大面积、超框、碎片及相似结果提醒不删除，也不修改实际Mask。
