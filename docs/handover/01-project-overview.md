# 01 项目总览

> 文档基线：2026-11-19；代码基线为 Git `27b41f6` 加当前未提交工作区。代码、部署和真机状态分层记录，以当前源码与实际证据为准。

## 1.1 项目身份

项目名称同时存在三种叫法：

| 场景 | 名称 |
| --- | --- |
| 中文小程序名 | 智络智绘 |
| 仓库名 | `dermatome-mapper` |
| GitHub 仓库 | `shingles` |

这三种名称指向同一个工程。不要把 GitHub 仓库名 `shingles` 理解成已经实现带状疱疹诊断。

## 1.2 要解决的问题

病灶在人体上的二维位置可以表达为像素或归一化多边形。神经皮节参考数据也可以表达为另一套归一化多边形。系统使用同一套二维几何核心回答：

- 病灶区域与哪些参考分区有正面积交集；
- 每个参考候选占当前病灶面积多少；
- 当前参考图谱尚有多少区域未覆盖；
- 多片病灶合并后与单片查看分别是什么关系。

AI 分割只负责从照片提取候选边界，不负责判断疾病、部位或神经节段。

## 1.3 用户路径

```mermaid
flowchart LR
  A[选择完整人体正/背面] --> B[手动圈选]
  A --> C[AI 辅助标注]
  C --> D[上传照片]
  D --> E[框选并运行 MobileSAM]
  E --> F[人工确认候选 Mask]
  F --> G[放置到人体]
  G --> H[移动/缩放/旋转并确认]
  B --> I[确认病灶几何]
  H --> I
  I --> J[FastAPI + Shapely]
  J --> K[参考图谱候选与覆盖比例]
  K --> L[人体高亮与标签筛选]
```

完整人体之外还有脚底、腋下、会阴局部流程。这些视图有独立 template、geometry、regionSet 和 atlas，不能把相同 `[0,1]` 数值自动互换。

## 1.4 产品能力边界

允许：

- 手工 Polygon 和 MultiPolygon；
- 运行内多片病灶管理；
- 多候选 AI Mask 的人工选择；
- 人体边界包含检查；
- 参考图谱几何交集；
- 特殊部位模拟匹配；
- 坐标调试与性能埋点。

禁止或未完成：

- 自动诊断带状疱疹；
- 从照片自动判断真实解剖部位；
- 自动确定真实受累神经根或神经节；
- 把几何覆盖比例解释为诊断概率；
- 把未经医学审核的模拟图谱宣传为临床标准；
- 跨模板复用历史几何而不校验版本。

## 1.5 系统边界

### 小程序负责

- 页面导航、Canvas 绘制、触摸交互；
- 人体和照片坐标转换；
- 运行期标注会话；
- 候选预览和用户确认；
- 请求结果的有效性复核；
- 折叠屏和安全区布局。

### FastAPI 负责

- 请求结构和资源预算校验；
- 人体/图谱版本和内容哈希校验；
- Shapely 交集、并集、面积与包含计算；
- 可选 MobileSAM 推理适配；
- 临时照片会话、鉴权和清理。

### 医学数据负责范围

来源图谱必须独立记录：

- 来源文件与 URL；
- 许可；
- 提取/配准方法；
- 模板绑定；
- 技术验证状态；
- 医学审核状态；
- 正式 mapping 是否启用。

当前所有图谱至少保留 `medicalReviewStatus=pending`，多数另有 `mappingEnabled=false`。

## 1.6 成功标准

工程成功不等于医学成功。交接时应分别判断：

| 层次 | 成功标准 |
| --- | --- |
| 几何工程 | 坐标不漂移、片/孔洞不丢失、版本不混用 |
| 数据工程 | 来源可追溯、哈希固定、旧版本可拒绝 |
| AI 工程 | 模型真实推理、临时图片清理、人工确认 |
| UI 工程 | 普通屏和折叠屏可操作，错误可恢复 |
| 医学有效性 | 仍需专业审核和临床验证，当前未完成 |
