## 25.2 ADR-001：微信原生小程序

背景：主要终端是微信手机用户，页面需要相机、相册、触摸 Canvas 和体验版发布。

决策：使用原生 TypeScript/WXML/WXSS 与 Canvas 2D，不引入跨端框架。

备选方案：

- React/Vue 跨端框架；
- WebView H5；
- 独立 App。

收益：

- 直接使用微信 `chooseMedia`、上传、Canvas、分包；
- 包体和运行时简单；
- 便于调用原生图片压缩；
- 不需要额外 Web 服务承载 UI。

限制：

- 平台差异显著；
- 真机验证不可替代；
- Canvas/基础库兼容复杂；
- 调试和自动操作能力有限。

证据状态：当前实现和历史文件可证。

## 25.3 ADR-002：二维人体与独立坐标

背景：目标是局部几何参考与快速交互，不要求三维表面配准。

决策：正背面各使用冻结二维模板和归一化坐标；特殊部位建立独立二维模板。

备选方案：

- 3D 人体网格；
- 单一二维正面图；
- 对背面使用正面翻转。

收益：

- 实现和手机性能可控；
- 标注、缩放和高亮直接；
- 数据可追溯和测试；
- 特殊部位可独立控制。

限制：

- 隐藏面、腋下、会阴无法由正背面坐标真实展开；
- 左右和朝向必须逐图核对；
- 不能把二维面积当体表真实面积；
- 不同视图不能自动互换。

是否可调整：未来可新增 3D 研究模块，但不能静默改变现有 V2 数据含义。

## 25.4 ADR-003：FastAPI、Shapely 与无数据库

背景：核心匹配是服务端几何计算，用户标注目前在会话内使用，不需要账号和病例持久化。

决策：小程序传归一化 Polygon，FastAPI 校验 identity，Shapely 计算交集；不使用数据库。

备选方案：

- 前端用 JS 几何库；
- PostGIS；
- Redis；
- 云端病例存储。

收益：

- 数学实现成熟；
- 后端可独立测试；
- 会话最小化；
- 部署资源少；
- 删除容易。

限制：

- 页面关闭后手工会话可能丢失；
- 没有审计追踪和用户同步；
- 复杂形状导致服务端 CPU 峰值；
- 高并发横向扩展尚未设计。

是否可调整：只有在出现明确病例持久化、账户和审计需求时才评估数据库。

## 25.5 ADR-004：照片坐标与人体坐标分离

AI 照片使用：

```text
photo_oriented_normalized_v1
```

人体使用：

```text
body_template_normalized_v1
```

关键决定：

- AI 确认结果保存照片坐标；
- 通过 `placementTransform` 生成独立人体草稿；
- 放置不修改原始 Mask/MultiPolygon；
- 删除 AI 会话后人体草稿仍存在；
- 匹配只接收人体坐标。

理由：

- 照片宽高比与人体不同；
- EXIF、缩放和裁剪改变照片基准；
- 解剖位置不能从局部照片自动推断；
- 用户必须确认人体位置。

禁止：直接把照片归一化坐标提交给 `/evaluate`。

## 25.6 ADR-005：完整保留 MultiPolygon 与孔洞

背景：AI 可能识别多个离散病灶，病灶内部也可能有正常皮肤。

决策：端到端保留外环、孔洞、多片；不合并成凸包，不静默删除小片。

理由：

- 凸包制造不存在的病灶面积；
- 只保留最大片区遗漏真实目标；
- 匹配面积和用户预期会偏离；
- 历史数据需要可解释。

限制：

- 拓扑校验成本高；
- 极端孔洞可产生长任务；
- 微信端几何库/包体不宜过重。

平衡：

- 源指纹缓存；
- Y 轴空间分桶；
- 快速可信变换路径；
- 最终确认仍做人体边界和裁剪结果校验；
- 不做无审计的默认简化。

## 25.7 ADR-006：全身自由放置

早期方案：用户先选粗身体区域，AI 病灶只在区域内放置。

当前决定：完整人体 front/back 自由放置，粗 region 只作初始上下文。

背景：

- 病灶可跨越旧粗区域；
- 用户实际位置比预选更可靠；
- 局部裁剪会让用户误以为只能放在某个小块。

保留限制：

- 必须位于人体有效皮肤；
- 部分越界由用户明确确认裁剪；
- 完全越界拒绝；
- front/back 独立切换；
- 删除/修改不能影响其他标注。

证据状态：V7.0 用户要求、台账和当前放置页可证。

## 25.8 ADR-007：完整 identity 与内容 hash

决策：请求绑定：

- template id/version；
- geometry id；
- region set id；
- atlas id/version；
- atlas content SHA；
- body content SHA；
- coordinate system。

理由：

- 同名版本可能指向不同生成内容；
- 只比较 view 会跨模板误匹配；
- 后端与前端必须从同一版本运行；
- 历史数据不能被新图谱静默改写。

结果：任何不一致返回版本错误并失败关闭。

限制：发布和缓存管理更严格；本地点位通常需要显式建立匹配的 atlas 版本。

## 25.9 ADR-008：特殊部位独立视图

决定：

- 左脚底/右脚底；
- 左腋下/右腋下；
- 会阴；
- 已退役的独立手掌入口不恢复。

原因：

- 掌跖、屈侧和会阴在正背面图中不可见或严重压缩；
- 同一 label 在不同视图代表不同二维几何实例；
- 左右朝向必须独立。

后果：

- 独立 viewId、templateId、atlasId、session；
- 不同视图匹配结果不能相加当面积；
- 特殊页面复用通用 V2/V4 思想但不复用坐标。

## 25.10 ADR-009：MobileSAM 可选运行时

决策：核心 FastAPI 可无 PyTorch 启动；AI 功能由 feature gate 和独立 venv 开启。

理由：

- 原针灸服务和几何 API不能因 AI 依赖失败而停服；
- 4 GB 级服务器资源有限；
- 模型权重较大，加载昂贵；
- AI 是辅助能力，不应成为所有页面的启动前提。

限制：

- 两种 venv 容易混用；
- 启动命令和部署更复杂；
- AI 故障要明确降级，不能伪装为普通匹配失败。

## 25.11 ADR-010：单 worker、单推理槽

决策：CPU 环境保持单 worker，AI 同时只执行受控推理数量。

理由：

- 避免每个 worker 重复加载模型；
- torch/CPU 推理可能瞬时占用大量 RSS；
- 与针灸服务共享主机；
- 内存比吞吐更关键。

代价：

- 多人同时使用时后续请求 429/等待；
- 需要容量提示；
- 不能把“单槽”隐藏在无限队列后。

未来：可在独立 AI 主机或明确资源预算下调整，但不能只改线程数。

## 25.12 ADR-011：临时 AI 会话

决策：

- 随机会话和能力令牌；
- 私有临时目录；
- 不公开静态路径；
- 所有者绑定；
- 确认放置 ready 后主动 DELETE；
- 空闲自动回收；
- 服务重启清理遗留；
- 不创建数据库。

当前证据：

- AI session 服务；
- `DELETE` 幂等；
- 2 分钟默认 TTL；
- 清理 timer/启动清理；
- 本机生命周期测试。

未完成：

- 前端心跳；
- 云端最新 TTL 和大图策略未部署验证；
- 云盘物理擦除不可保证。

## 25.13 ADR-012：模拟图谱必须显式

决定：腋下/会阴等人造全覆盖分区使用：

- `SCHEMATIC`；
- `NOT_MEDICALLY_VALIDATED`；
- `INTERACTIVE_SIMULATION`；
- `ARTIFICIALLY_CONSTRUCTED`；
- `medicalReviewStatus=pending`。

理由：

- 可用来源图谱覆盖不足；
- 客户需要交互演示；
- 推定边界不能冒充原图精确提取；
- 100% 覆盖只表示模拟区域覆盖，不是医学准确率。

禁止：在公开结果中删除免责声明后显示为临床定位。

## 25.14 ADR-013：客户端高清照片预处理

决策：

- 原图可较大；
- 处理图约束在 8 MiB/3MP/1920 最长边；
- Canvas 超大时不直接解码；
- 大 JPEG优先原生缩图；
- 交互和模型以处理图为基准；
- 保存明确的方向、尺寸和映射。

理由：

- 手机上传流量和内存；
- 服务端 OOM；
- MobileSAM CPU 不需要原分辨率和全部像素；
- 用户不应手动压缩。

限制：

- `wx.compressImage` 平台差异；
- 纯 HEIC 不保证；
- 大 PNG/WebP 可能要求转存；
- 真机未覆盖常见机型。

## 25.15 ADR-014：交互缓存与最终精确计算

决策：

- 拖动期间显示缓存贴片的相似变换；
- 每帧不重算整个 MultiPolygon；
- 松手后执行一次正式几何和边界校验；
- 最终确认再执行完整校验和必要交集/裁剪；
- 旧 revision 的 Canvas ready 不能提交新几何。

理由：交互体验需求与几何可信需求不同。

限制：

- 预览与确认结果必须最终一致；
- Canvas ready 生命周期复杂；
- 极端几何仍需性能预算；
- 不能用“预览看起来可以”代替最终合法性。

## 25.16 ADR-015：原生分包

决策：

- 主包保留起始页与公共人体交互；
- clinical 分包保留标注/结果/AI/放置/调试；
- special 分包保留特殊部位；
- 图谱用无损坐标编码压缩生成文件；
- 分包只引用主包共享代码，不互相非法引用。

理由：

- 微信单包 2 MB；
- 主包过大会阻塞启动；
- AI/特殊功能可延迟加载。

限制：

- 路由和资源路径更易出错；
- 新增大图谱仍可能让分包接近上限；
- 必须持续运行 package checker。
