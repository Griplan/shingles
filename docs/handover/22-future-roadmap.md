# 22 后续路线图

> 文档基线：2026-11-19；代码基线为 Git `27b41f6` 加当前未提交工作区。本节是交接建议，不是客户已确认的排期。

## 22.1 先处理版本分叉

当前最重要的后续工作不是增加新功能，而是建立可复现的版本链：

```mermaid
flowchart LR
  W[当前未提交工作区] --> F[冻结并分组审阅]
  F --> C[创建可追溯提交或发布分支]
  C --> B[生成后端/前端/图谱/模型版本清单]
  B --> L[本地全量回归]
  L --> D[部署后端并可回滚]
  D --> T[上传新体验版并设为体验版]
  T --> R[Android/iOS 真机验收]
```

当前已知分叉：

| 层 | 已知状态 | 不能据此推断 |
| --- | --- | --- |
| 当前工作区 | V7/P8/P9/P11.2/P12.1 等后续改动 | 不代表已提交、已部署 |
| Git HEAD | `27b41f6`“更改流程” | 不代表包含当前工作区全部文件 |
| 远端 `main` | `a7bb1b8`“修改人体模型流程前” | 不代表最新部署版本 |
| 云端 | 最近完整证据是 V6.7 | 不代表含当前本地增量 |
| 微信 | `0.6.8` 曾上传成功 | 没有证据证明它是当前体验版 |
| 真机 | `NOT_RUN` | 不能由模拟器或自动测试替代 |

在做任何新功能前，应由项目负责人确认：

1. 哪些未提交文件属于同一可发布版本；
2. 是否需要把后续改动拆成功能提交，而非一次大提交；
3. 当前要部署的是“稳定版”还是“开发试验版”；
4. 是否保持 P12.1 的 50 MiB/5000 万像素/120 秒策略；
5. 体验包是否允许进入受控体验；
6. 医学模拟图谱在公开环境中的提示和门禁。

## 22.2 优先级定义

| 优先级 | 验收含义 |
| --- | --- |
| P0 | 不解决会导致数据误用、环境不一致、隐私暴露或核心流程不可用 |
| P1 | 影响主要用户流程、真机稳定性或运维可靠性 |
| P2 | 影响性能、可维护性、测试成本或体验 |
| P3 | 长期优化，当前不影响主流程 |

路线图区分三种来源：

- **客户已明确要求**：已有用户消息或台账记录；
- **历史尚未完成项**：现有报告和任务台账已列出；
- **交接建议**：本次文档根据代码与风险提出的建议，未获排期。

## 22.3 短期：稳定与可发布化

### P0.1 冻结并审计当前工作区

来源：历史尚未完成项。

工作：

- 按前端、后端、图谱、测试、文档、部署配置分组审阅；
- 记录每个文件属于哪个版本；
- 禁止 `git reset --hard`、`git clean`、整库 checkout；
- 对敏感文件执行 Git 忽略和内容扫描；
- 建立新的发布 manifest。

完成条件：

- 每个待发布文件有来源与用途；
- 生成 commit 或不可变发布目录；
- 可从发布目录重建测试输入；
- 不把所有历史功能混成一个不可回滚的大提交。

### P0.2 建立版本四联表

来源：交接建议。

至少记录：

| 维度 | 需要记录 |
| --- | --- |
| 小程序 | 构建号、体验版号、上传时间、Git 代码基线 |
| 后端 | release manifest、服务启动时间、环境变量摘要 |
| 图谱 | atlasId/version、manifest SHA、审核状态 |
| AI | 权重 SHA、MobileSAM source commit、推理配置 |

版本不一致时，前端和后端都应失败关闭，不能猜兼容。

### P1.1 同步当前后端安全增量

来源：P12.1 历史记录与当前工作区。

候选变更：

- 50 MiB 实际文件上限；
- 5000 万像素源图上限；
- JPEG/PNG/WebP 安全解码和推理前缩图；
- 默认 120 秒 AI 闲置 TTL；
- Nginx AI 路径 51 MiB 请求体模板；
- 独立清理任务与重启清理。

部署前必须实测：

- 大图 CPU/RSS；
- 单 worker 单推理槽；
- 原始针灸服务无重启；
- `nginx -t`；
- 150/300 秒空闲会话行为；
- 推理中删除竞争；
- 云端 410/429/504 错误契约。

### P1.2 上传当前体验版并做真机验收

来源：客户明确要求与历史未完成项。

最小真机矩阵：

- Android 一台；
- iOS 一台；
- 竖屏和横屏；
- 1200 万、2400 万、4800 万像素公开 JPEG；
- EXIF 旋转；
- 相册与拍照；
- 人工标注、AI 分割、确认、放置、匹配；
- Wi-Fi 与移动网络；
- 弱网、429、超时和恢复。

只有新包在真机打开且完成流程后，才能标记 `TRIAL_VERIFIED`。

### P1.3 决定是否增加 AI 心跳

来源：P12.1 明确限制。

服务端默认空闲 120 秒会在没有请求时清理会话。当前前端没有心跳，因此长停留不等于会话可持续。

建议实现条件：

- 页面可见时低频心跳；
- 不发送照片或几何；
- hidden/unload 立即停止；
- 弱网退避；
- 心跳失败不掩盖原错误；
- 推理运行中由服务端活动状态保护；
- 心跳不能绕过 Bearer 或会话能力令牌。

未完成前，产品应允许用户重新上传，而不是展示无限加载。

## 22.4 中期：核心流程稳定性

### P1.4 真机 Canvas 与手势性能

需要测量：

- 人体首帧；
- 拖动贴片的长任务；
- 2000/6018 顶点与 301/1000 孔洞；
- 结果 Canvas 首帧；
- 折叠屏 resize；
- FPS、触摸延迟和内存。

现有 Node/微信工具数据只能作为回归基线。若低端机仍出现长任务，可再评估：

- 分段校验；
- Worker；
- 更保守的源轮廓噪声处理；
- 动态层缓存；
- 减少不必要的完整节点重绘。

不能先删除孔洞、小片区或最终人体校验来换取表面流畅。

### P1.5 统一错误呈现

把用户可恢复错误分为：

| 类型 | 用户动作 |
| --- | --- |
| 网络不可达 | 检查网络，重试 |
| 401/403 | 重新建立受控会话，不显示 token |
| 409 版本不一致 | 更新小程序或后端 |
| 410 会话过期 | 重新上传 |
| 413/422 输入超限 | 按安全上限重新处理 |
| 429 忙碌 | 稍后重试，不无限轮询 |
| 504 超时 | 重试一次后回到可编辑状态 |
| Canvas 初始化失败 | 自动重试一次，再给手动重试 |

### P2.1 MobileSAM 特征缓存

来源：历史建议，尚未实施。

可能收益：同一照片多次框选或前景点调整时复用图像编码。

前置条件：

- 明确 Predictor 状态的生命周期；
- 删除会话时同步释放特征；
- 单 worker、单推理槽下测试并发；
- 缓存大小上限；
- 不跨会话或跨图片复用；
- 精度与耗时对照。

这是独立性能项目，不能与医学模型替换混在一起。

### P2.2 前端基础库兼容矩阵

至少验证：

- `wx.getWindowInfo()` 缺失回退；
- `wx.compressImage` 是否支持宽度/高度参数；
- PNG/WebP/JPEG 的平台差异；
- Canvas `createImage()` 缺失；
- 相册/相机返回格式；
- 折叠屏 resize 事件顺序。

## 22.5 中长期：可用性与维护性

### P2.3 部署可观测性

建议保持轻量：

- health/ready 已有接口；
- systemd 重启与 RSS；
- 临时会话数量；
- AI 推理耗时；
- 429/504 比例；
- 临时目录文件数和最老年龄；
- Nginx 5xx；
- 原针灸服务健康状态。

先证明现有日志足够，再考虑 Prometheus 等额外服务。

### P2.4 测试数据治理

建立合法测试图片登记：

- 来源 URL；
- 许可；
- 去标识化状态；
- 文件 SHA；
- 允许用途；
- 是否进入仓库；
- 预期操作；
- 是否有人工 Mask。

禁止用模型输出当自身 ground truth 算 Dice/IoU。

### P2.5 特殊部位图谱替换流程

每个特殊部位最终应从“模拟”升级为“有来源且审核的参考图谱”：

1. 记录原始 SVG/path；
2. 固定模板和坐标；
3. 明确左右、朝向和遮挡面；
4. 得到医学人员逐区审核；
5. 形成正式 atlas 版本；
6. 运行几何和匹配回归；
7. 保留旧模拟版本供历史追溯；
8. 不静默改变历史结果含义。

正式图谱未通过前，继续保留 `SCHEMATIC`、`NOT_MEDICALLY_VALIDATED` 和面向用户的免责声明。

## 22.6 长期：专用病灶分割研究

只有在以下条件满足后才考虑微调：

- 有合法授权、去标识化的数据；
- 有皮肤科/医学专业人员标注；
- 明确标注协议和仲裁；
- 留出独立测试集；
- 报告 Dice/IoU、敏感性、误选面积、多片保留和失败案例；
- 有模型卡、数据卡和许可证；
- 不把研究指标称为临床准确率；
- 有回滚到通用 MobileSAM 的路径。

当前项目没有足够证据支持“MobileSAM 已临床验证”或“微调可直接上线”。

## 22.7 明确不属于当前路线

除非用户后续明确授权，不应把以下事项当作默认下一步：

- 三维人体；
- 自动识别疾病类型；
- 自动判定受累神经根；
- 云端病例持久化；
- 引入数据库/Redis/K8s；
- 对外提供诊断报告；
- 改变已退役独立手掌入口；
- 将模拟图谱升级为正式医学数据。

## 22.8 路线图准入门槛

每个阶段进入下一阶段前至少满足：

| 阶段门 | 必须通过 |
| --- | --- |
| 开发完成 | TypeScript、单测、必要后端测试 |
| 本地验收 | 分包、微信编译、关键流程 |
| 部署 | manifest、备份、health/ready、原服务回归 |
| 体验版 | 新包上传并显式设为体验版 |
| 真机 | Android/iOS 主流程与失败恢复 |
| 医学声明 | 来源、许可、审核状态和公众免责声明 |
